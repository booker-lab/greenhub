변경 파일이 서로 겹치지 않는다. U2의 `redelivery-payment.ts` 문구 변경(D-03·D-18)은 목록 행(`OrderCard.tsx`)에도 그대로 반영되며, U4는 이 파일을 읽기만 한다. 두 단위가 같은 "배송 목록으로" 버튼을 따로 만들 수 있으므로 통합 때 한 번 맞춘다.

운영 연락처(D-01·D-18·D-19)는 새 설정값을 만들지 않고 소비자 푸터가 쓰는 사업자 정보의 고객센터 번호를 읽는다. 세 단위가 같은 값을 쓰므로, 읽는 방법은 U1이 먼저 정하고 U2·U4는 같은 방법을 따른다(통합 때 하나로 맞춘다). 재배송비 기준 금액 10,000원은 기사 앱 `delivery-hold-form.ts`와 판매자 보류 창에 각각 상수로 두고, 서로 같은 결정임을 주석에 적는다(앱 간 import 없이 옮긴 기존 상한 `MAX_REDELIVERY_FEE_KRW`와 같은 방식).

### 단위별 세부

- **U1**
  - D-01: API가 승인 전 기사 거절(`auth.service.ts:577-579`, 이메일 로그인 `:373-375`)에 `code: 'DRIVER_APPROVAL_PENDING'`을 싣는다(상태 403·메시지는 그대로, 관리자 거절 code `KAKAO_LOGIN_DRIVER_APP_ADMIN_ACCOUNT`와 같은 방식). 기사 앱 카카오 signIn 콜백이 이 code를 읽어 승인 대기 안내("가입 신청이 접수됐어요. 승인되면 다시 로그인해 주세요" + 고객센터 번호)로 보내고, 다른 역할 거절은 "기사용 계정이 아니에요"로 나눈다.
  - D-13: proxy·`signOut` 이동에 현재 경로를 `callbackUrl`로 싣고, 카카오 `redirectTo`가 그 값을 쓴다(같은 출처 경로만 허용). 로그인 화면에 만료 안내를 보인다.
  - D-22: 기사 세션이 있으면 `/login`에서 `/board`(또는 `callbackUrl`)로 보낸다. `callbackUrl=/login` 자기 순환을 막는다(소비자 C-27에서 실제로 생긴 회귀).
- **U2**
  - D-02: "수거 완료 / 배송 시작"·"배송 재개"에 확인 창을 둔다(주소·상품 수·손님 알림 사실). 확인 전에는 요청을 보내지 않는다. 기존 in-flight·불확실 수렴 규칙은 그대로 둔다.
  - D-03: `MISSING` + `canPay=true` + `requiresRecovery=false`를 "재배송비 결제 전 · 결제되면 다시 배송할 수 있어요"로 표시한다(결제 요청 알림톡은 판매자가 "재배송 준비로 돌리기"를 눌러야 나가므로 "손님 결제 대기"로 단정하지 않는다, 런북 §6.4). 버튼 잠금 판정(`isDeliveryStartAllowed`)은 바꾸지 않는다.
  - D-07·D-15·D-24: 보류 유형 기본 선택 없음, 유형·입력 변경 시 이전 오류 지움, 이름을 "배송 보류"로 통일.
  - D-09: "고객 책임"을 체크하면 재배송비 칸을 기준 금액 10,000원으로 채운다(기사가 바꿀 수 있음, 상한 50,000원 검사는 그대로). 체크를 풀면 비운다. 기상 악화는 지금처럼 칸을 잠근다.
  - D-08: 사유 칸 이름·도움말에 "손님에게 보임·보류 알림 발송"을 적는다.
  - D-14: 불확실 안내를 한 면·한 버튼으로 합치고 "명령" 표현을 없앤다. 재전송 금지 규칙(코드 주석의 NO_RESEND)은 그대로다.
  - D-16·D-17: 앱 안 기록이 없으면 뒤로가기를 `/board`로, 주문 없음 화면에 이유와 "배송 목록으로" 버튼.
  - D-18: 재배송비 상태 문구에서 "서버" 표현을 빼고 짧게 쓴다.
- **U3**
  - D-05: 촬영 화면 제목 아래에 동·호수와 받는 분을 보인다(업로드 전 이미 읽는 기사 주문 조회 응답 재사용).
  - D-06: 미리보기 상태의 버튼 배치를 세로로 쌓거나 확정 문구를 줄여 390px·360px에서 잘리지 않게 한다.
  - D-04: 완료 수렴(정상 완료와 "서버가 이미 완료" 수렴 모두) 뒤 목록 이동 전에 완료 알림을 띄운다. 불확실 경로에서는 띄우지 않는다.
  - D-21: JPEG 아닌 사진 안내 문구만 바꾼다.
- **U4**
  - D-10: API 목록·상세 응답에 `assignedToMe`(boolean)를 싣고, 수거 대기 탭을 "내 수거"와 "맡을 수 있는 주문"으로 나눈다.
  - D-12: 제목을 "배송 목록"으로 바꾸고, API가 회차 배송 시작 시각을 싣으면 오늘이 아닌 주문 행에 배송일을 쓴다. 회차 문서 조회는 노출 판정이 이미 하는 조회를 재사용하고 새 쿼리 수를 늘리지 않는다.
  - D-17: 앱 공통 한국어 `not-found.tsx`.
  - D-19: 배송 중·보류 주문이 있으면 로그아웃 확인(목록 조회 1회). 내 정보에 "운영팀에 연락"(고객센터 번호) 줄.
  - D-20: 지도 행 번호를 상태 묶음으로 바꾸고 동·호수를 보인다.
  - D-23: 인증 오류 화면에서 "다시 시도"를 뺀다.
- **U5**
  - D-09: 판매자 보류 창도 "고객 책임" 선택 때 재배송비 칸을 10,000원으로 채운다(바꿀 수 있음). 기사 앱과 같은 결정임을 상수 주석에 적는다.

## 4. 발행과 후속 후보

- 감사 PR(#836)은 감사 문서(`findings.md`, `plan.md`, `screenshots/`)만 담는다.

독립 검토에서 고친 것:

- 완료 내역 사진이 서비스 워커 `cross-origin` 캐시에 1시간 남던 것 → Storage 호스트·`deliveryPhotos` 경로를 NetworkOnly로, 남은 캐시 삭제

- 대기열: 보내기 직전에 시도 기록, 로그아웃 상태에서도 12시간 만료 정리
- 종결: 오래된 PENDING 재배송비를 PortOne에 확인(결제됨이면 확정 후 거절, 확인 불가면 거절), 회차 취소 중 거절, 정산이 빠지면 판매자 화면 "정산 다시 맞추기", 아침 점검이 종결 주문을 배송 마감 지남으로 올리지 않게
