### 검증(PR 단계, 로컬)

1. 단위마다: 소비자 단위 테스트(`pnpm --filter consumer test`), 타입 검사(`tsc --noEmit`), 린트. 문구를 의도적으로 바꾸면 그 문구를 고정한 소스 검사 테스트도 함께 고친다. 새 판단 로직은 순수 함수로 빼서 단위 테스트를 붙인다.
2. 단위마다 독립 검토 에이전트가 diff를 반박 관점으로 검토한다. 막는 문제가 있으면 고친다.
3. 통합 뒤: 소비자 운영 빌드(`next build`), 감사 때 쓴 로컬 스택 Playwright 여정으로 고친 항목을 다시 실행해 전후를 확인한다.
4. 원격 Preview·E2E는 쓰지 않는다(`AGENTS.md` §0-9, 배포 직전 release train에서 1회).

### C-02 결정 자료

- 코드 사실: 결제 실패 알림(`Transaction.Failed`)이 오면 결제 대기 주문을 `payment_failed`로 취소하고 예약을 반환한다(`apps/api/src/payments/payments.service.ts` 78-82행). 감사는 알림이 오지 않는 로컬 환경이라 예약이 쌓였다. 사용자가 결제창을 닫을 때 PortOne이 실패 알림을 보내는지는 공식 문서로 확인하지 못했다.
- 판단 순서: 시나리오 H에서 취소한 시도가 곧 "주문 취소"가 되면 **API 변경이 필요 없다**(BACKLOG `ROUND-PAYMENT-RETRY-DOUBLE-HOLD`는 그대로 두고 감사 결과만 기록). "결제 확인 중"으로 남으면 API 변경을 검토한다.
- API 변경안(필요할 때): 같은 `clientOrderRequestId` 재요청은 주문이 `PENDING`이고 예약이 `HELD`·만료 전일 때만 기존 주문을 돌려주고, 그 밖(취소·만료)에는 명시적 409 코드로 거절한다. 소비자 앱은 그 코드를 받을 때만 새 ID로 한 번 다시 시도하고, 상품·금액·입력이 그대로면 같은 ID를 탭 범위에 저장해 다시 쓴다. 2026-10-04 결정(이전 예약을 반환하지 않음)과 늦은 결제 재확보·자동 환불 흐름은 건드리지 않는다. 같은 ID가 취소된 주문으로 이어지지 않으므로 "결제 승인 → 자동 환불"을 막는다.

### C-28 배송 보류 안내 문구 초안(검토용)

지금 주문 상세는 판매자·기사가 직접 입력한 `reasonMessage`를 그대로 보이고 "고객 책임: 해당/없음"만 덧붙인다. 알림톡은 일부러 사유 코드별 고정 문구만 쓴다(`DELIVERY_HOLD_CUSTOMER_REASONS`, `apps/api/src/orders/orders-lifecycle.service.ts`). 주문 상세도 고정 문구를 기본으로 하는 초안이다. 정책 사실: 기상(`WEATHER`)은 고객 책임·재배송비가 없고 새 배송 일정이 필수다. 그 밖에는 고객 책임이면 재배송비가 있고, 아니면 없다(`delivery-hold-policy.ts`). 재배송비는 결제가 끝나야 재배송이 시작된다.

| 사유 코드 | 제목 | 본문 초안 | 다음 행동 |
|---|---|---|---|
| `WEATHER` | 날씨 때문에 배송을 미뤘어요 | 안전한 배송이 어려워 배송을 미뤘어요. 재배송비는 없어요. | 새 배송 일정(`nextDeliveryAt`) 표시 |
| `ACCESS_UNAVAILABLE` (고객 책임) | 출입이 어려워 배송하지 못했어요 | 공동현관·출입 방법을 확인하지 못해 배송하지 못했어요. 재배송비 ○원을 결제하면 다시 배송해요. | 재배송비 결제, 출입 방법 문의(고객센터) |
| `ADDRESS_ISSUE` (고객 책임) | 주소를 찾지 못해 배송하지 못했어요 | 적어 주신 주소로 배송지를 찾지 못했어요. 재배송비 ○원을 결제하면 다시 배송해요. | 재배송비 결제, 주소 확인 문의 |
| `CUSTOMER_UNREACHABLE` (고객 책임) | 연락이 닿지 않아 배송하지 못했어요 | 받는 분과 연락이 닿지 않아 배송하지 못했어요. 재배송비 ○원을 결제하면 다시 배송해요. | 재배송비 결제, 연락 가능한 번호 확인 |
| 그 밖·고객 책임 아님 | 배송을 잠시 미뤘어요 | 저희 사정으로 배송이 늦어지고 있어요. 재배송비는 없어요. | 다음 연락·배송 일정 표시 |

정해야 할 것: 사유별 문구 확정, 판매자·기사 자유 입력을 고객 화면에 계속 보일지(보인다면 "기사 메모"처럼 구분), 재배송비를 결제하지 않을 때의 처리(기한·취소 여부) 안내 문구.
