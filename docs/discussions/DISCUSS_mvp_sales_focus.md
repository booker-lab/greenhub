# DISCUSS: MVP 판매 방식 축소와 선택 집중

## 1. 현재 상황 요약
- 현재 웹앱에는 택배, 거점픽업, 직배송 같은 배송 방법과 공동구매 같은 구매 방법이 함께 존재한다.
- MVP 단계에서는 각 방식의 운영 전제 조건이 아직 충족되지 않았다.
- 거점픽업은 계약된 거점이 없고, 택배는 포장재와 발송 표준이 없으며, 직배송은 지역 수요와 배송 밀도가 검증되지 않았다.
- 공동구매는 참여자 모집이 선행되어야 하므로 초기 주문 경험을 복잡하게 만들 수 있다.
- 당근 비즈니스를 활용해 지역 수요를 먼저 만들고, 그린러브 웹앱은 주문 접수와 신뢰 형성의 중심으로 운영하는 방향을 논의한다.

## 2. 진행 중 결정
- [열림] MVP에서 고객에게 약속할 기본 구매 방식
- [열림] MVP에서 숨기거나 보류할 배송 및 구매 옵션
- [열림] 당근 비즈니스와 그린러브 웹앱의 역할 분리

## 3. 합의할 방향과 범위
- 방향: 아직 운영 계약과 물류 표준이 없는 기능은 기본 옵션에서 제외하고, 검증 가능한 하나의 주문 흐름에 집중한다.
- 이번에 하는 것: 판매 방식, 배송 방식, 공동구매 노출 여부를 논의한다.
- 하지 않는 것: 앱 코드 수정, 결제 구현, 관리자 기능 확장, 배송 자동화 구현.
- 완료 기준: MVP에서 기본으로 노출할 주문 흐름과 보류할 옵션이 정해진다.
