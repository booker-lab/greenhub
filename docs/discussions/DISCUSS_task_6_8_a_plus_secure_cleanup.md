# DISCUSS: Task 6.8 A+ 보안·작업 공간 정리

## 1. 현황 요약

- **이번 discuss에서 끝까지:** 기존 사용자 작업을 보존하면서 검증 SHA 기준과 노출 비밀값 위험을 안전하게 분리한다.
- 최종 검증 SHA `39fdb2c28c45b5c7658519181e41845bb24be2fd`는 로컬 객체 DB에 commit으로 존재한다.
- 현재 HEAD `8bcfb76b8efeac71c5e84a4743bedc2d6838d2c3`은 검증 SHA의 조상이며 정확히 2개 커밋 이전이다.
- 현재 작업 트리의 `pnpm-lock.yaml`과 `scripts/package.json`은 검증 SHA의 변경과 겹친다.
- 기준 커밋 역사에 실재형 PortOne 비밀값이 있었으므로 문서 치환과 artifact 삭제만으로 노출을 해소할 수 없다.

## 2. 진행 중 결정

- [확정] A+를 채택한다 — 비밀값 폐기·회전을 worktree 분리보다 먼저 수행한다.
- [확정] 검증 SHA의 별도 worktree를 만들어 현재 작업 트리와 후속 작업을 물리적으로 분리한다.
- [확정] Git 역사 재작성과 force push는 이번 계획에서 수행하지 않는다.
- [확정] 기존 작업 트리에서는 승인된 생성물과 정확히 검증된 TEMP 사본만 제거한다.
- [확정] readiness·credential JSON은 원문을 출력하지 않고 파일별 소유권을 판정한다.

## 3. 합의된 방향 · 범위

- **방향:** 비밀값 무효화 → 별도 worktree → 기존 작업 트리 정리 순서로 진행한다.
- **이번에 하는 것:** 비민감 노출 감사, 승인된 PortOne 비밀값 폐기·회전, 검증 SHA worktree 생성, cleanup 허용 목록 작성, 승인된 생성물·TEMP 정리, JSON 소유권 판정.
- **안 하는 것:** 애플리케이션 동작 변경, Git 역사 재작성, force push, 운영 `salesMode` 변경, Task 6.8 역사적 증거 변조.
- **완료 기준:** 이전 비밀값이 인증에 실패하고 새 비밀값이 인증 경계를 통과하며 새 worktree HEAD가 검증 SHA와 일치한다.
- **완료 기준:** 기존 작업 트리의 사용자 변경과 역사적 증거가 보존되고 삭제 항목은 승인된 허용 목록과 일치한다.
- **엣지 케이스:** 비밀값 활성 여부가 불명확하면 활성으로 간주하고 먼저 회전한다.
- **엣지 케이스:** 새 worktree 경로나 브랜치가 이미 존재하면 덮어쓰지 않고 중단한다.
- **엣지 케이스:** cleanup 후보에 인증 상태·개인정보·manifest가 있으면 내용을 출력하지 않고 소유권 판정 대상으로 격리한다.
- **엣지 케이스:** 이전 비밀값 무효화는 성공했지만 새 값 검증이 실패하면 기존 값을 되살리지 않고 서비스 소유자에게 에스컬레이션한다.
- **엣지 케이스:** Git 역사 스캔이 노출 값을 계속 찾더라도 회전 증거와 역사 정리 여부를 분리해 판정한다.
