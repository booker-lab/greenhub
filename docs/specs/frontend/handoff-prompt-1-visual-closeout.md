# 핸드오프 프롬프트 1번: 육안검증 종결 가지

> 작성: 2026-06-06
>
> 목적: 핸드오프 번호가 순차 개발 단계처럼 해석되는 문제를 막고, 1번을 **육안검증 완료 가지**로 고정한다.

## 분기 정체성

**프롬프트 1번은 새 기능 개발이나 릴리즈 웨이브가 아니다.**

이 가지는 `visual-verify-handoff-20260601.md`와 원본 SSOT 체크리스트의 보류·종결 상태를 이어받아, 현재 조건에서 닫을 수 있는 육안검증 항목만 닫는 마감 흐름이다.

## 읽어야 할 문서

1. `docs/specs/frontend/visual-verify-handoff-20260601.md`
2. `docs/specs/frontend/pending-visual-verify.md`

4. `docs/specs/frontend/manual-visual-verify-checklist.md`
5. `docs/specs/frontend/visual-verify-fix-backlog.md`

## 첫 진입점

**먼저 새 코드를 작성하지 않는다.**

아래 잔여 묶음 중 현재 인증·운영 데이터·쓰기 승인 조건으로 실행 가능한 최상위 묶음을 하나 고른다. 2026-06-06 현재 이미 종결된 묶음은 `#146~#148`, `#173`, `#49~#51`, `#53~#58`, `#208~#209`이며, 남은 수동 조건 항목 `#43`, `#79`는 이번 세션 조건 부재로 `[-]` 처리했다.

| 후보 | 성격 | 진입 조건 |
|---|---|---|
| `#43` | 겸직 계정 프로필 저장 | `[-]` 운영 쓰기 승인 또는 되돌릴 수 있는 겸직 계정 데이터 없음 |
| `#79` | 정지 사용자 refresh token 차단 수동 확인 | `[-]` 정지 소비자 refresh token 또는 별도 정지 테스트 계정 없음 |

## 완료 기준

- 원본 체크리스트의 해당 항목을 `[x]`, `[-]`, `[ ]` 중 하나로 즉시 갱신한다.
- 결함이 발견되면 `visual-verify-fix-backlog.md`에 `VF-*`로 기록한다.
- 운영 데이터를 바꾸는 버튼은 사용자 승인 없이 누르지 않는다.
- 세션 종료 시 `docs/memory.md`에 닫은 번호와 보류 사유를 1~2줄로 남긴다.

## 현재 결론

2026-06-06 기준으로 실행 가능한 핸드오프 1번 육안검증은 종료했다. `#43`, `#79`는 조건 부재로 이번 세션에서는 확인 불가(`[-]`)이며, 운영 쓰기 승인 또는 전용 테스트 계정이 확보되면 별도 재개한다.
