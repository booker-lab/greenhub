# 소비자 앱 육안검증 후속 작업 정리

기준일: 2026-06-17

## 1. 목적

소비자 앱 운영 도메인 육안검증 중 발견한 후속 개선 사항을 한 문서에 모아, 홈·카테고리·상점·공구·장바구니·MY 탭의 개선 작업을 탭별로 추적한다.

이 문서는 즉시 구현 문서가 아니라 **육안검증에서 확인된 문제, 판단 근거, 후속 작업 우선순위**를 정리하는 작업 큐다.

## 2. 기록 원칙

- **화면 신뢰도와 구매 판단을 해치는 문제를 우선 기록한다.**
- **기술적 버그 수정 여부와 UX 완성도를 분리해서 판단한다.**
- **운영 데이터 정리 문제와 프론트엔드 표시 개선 문제를 섞지 않는다.**
- **각 항목은 탭, 문제, 영향, 후속 방향, 상태를 함께 남긴다.**

## 3. 상태 기준

| 상태 | 의미 |
| --- | --- |
| `확인 필요` | 캡처나 화면 제보는 있으나 재현 조건을 더 확인해야 함 |
| `작업 후보` | 문제와 방향이 확인됐으나 아직 구현 계획으로 고정하지 않음 |
| `설계 필요` | 별도 선 설계 문서 또는 도메인/API 판단이 필요함 |
| `구현 대기` | 범위와 완료 기준이 충분히 명확해 구현 가능함 |
| `완료` | 구현·검증·배포까지 끝남 |

### 홈 탭 현재 판단

- [x] 공동구매 이미지가 홈 전체를 덮던 기술적 버그는 해결됐다.
- [x] 공동구매 이미지가 카드 내부에 갇히고 하단 내비게이션도 유지된다.
- [x] `0/50개 · 50개 더 필요` 수량 문구는 노출된다.
- [ ] 홈 UX 기준으로는 공동구매 미리보기 카드 크기가 과도해 추가 다듬기가 필요하다.
- [ ] `마감 확인 중` 상품을 홈의 진행 중 섹션에 둘지 여부는 공구 상태 기준과 다시 맞춰야 한다.

## 5. 카테고리 탭 후속 작업

| ID | 우선순위 | 문제 | 영향 | 후속 방향 | 상태 |
| --- | --- | --- | --- | --- | --- |
| C-CATEGORY-01 | 완료 | URL 기반 탭·정렬·검색 진입은 운영 도메인에서 정상 동작함 | 공유 링크, 새로고침, 조건 유지 흐름이 안정화됨 | 현재 구현 유지. 회귀는 카테고리 E2E로 고정 | 완료 |
| C-CATEGORY-02 | High | 공동구매 탭에 `모집 실패` 상품이 그대로 노출됨 | 소비자는 공동구매 탭을 참여 가능한 공구 목록으로 기대할 수 있어 구매 가능 여부를 오해할 수 있음 | `saleType=group` 단순 필터와 `recruiting` 상태 필터를 분리해 정책 결정. 참여 가능 공구만 노출할지, 실패/종료 상품을 별도 상태 영역으로 둘지 선 설계 필요 | 설계 필요 |

### 카테고리 탭 현재 판단

- [x] `/category`, `/category?sort=price_asc`, `/category?saleType=group`, `/category?category=orchid&sort=price_asc`에서 URL 기반 탭·정렬 상태가 정상 반영된다.
- [x] 검색 아이콘은 `/search`로 정상 진입한다.
- [x] 콘솔에는 기능 오류가 아니라 CSS preload 경고만 보인다.
- [ ] 공동구매 탭의 의미가 `공동구매 상품 전체`인지 `참여 가능한 공동구매`인지 정책 결정이 필요하다.

### 상점 탭 현재 판단

- [x] 상점명·주소 검색은 운영 화면에서 결과를 좁힌다.
- [x] 검색 결과 없음 상태와 `검색 초기화` 버튼이 표시된다.
- [x] 정렬은 고정 버튼형 컨트롤로 교체되어 드롭다운 팝오버를 열지 않는다.
- [x] 상점 상세에서 판매 상품 그리드와 상품 상세 진입이 정상 동작한다.
- [ ] 깨진 주소 문자열은 프론트 버그가 아니라 운영 데이터 정리 과제로 분리한다.
- [ ] 상품 0개 상점의 노출 정책은 구매 가능 상점 우선 탐색 관점에서 별도 결정이 필요하다.
- [ ] 정렬 문구는 기능적으로 동작하지만 소비자 이해도 기준으로 더 명확하게 다듬을 수 있다.
- [ ] 상점 상세 상품 카드는 모바일 탐색 밀도 기준으로 추가 개선 여지가 있다.

## 9. 다음 작업 후보

1. 홈 공동구매 미리보기 컴팩트 카드 개선안을 별도 선 설계로 고정한다.
2. 홈에서 `마감 확인 중` 상품을 숨길지, 정보 확인 상태로 축소 표시할지 공구 상태 유틸과 맞춘다.
3. 카테고리 공동구매 탭에서 모집 실패·마감·정보 확인 필요 상품을 숨길지 별도 영역으로 분리할지 정책을 정한다.
4. 상점 주소 깨짐은 운영 데이터 정리 과제로 분리하고, 대상 상점 ID를 육안검증 중 기록한다.
5. 상품 0개 상점의 표시 정책을 정하고 목록 정렬·배지·제외 기준 중 하나로 고정한다.
6. 상점 정렬 버튼 문구를 `상품 많은순`, `거점 많은순`처럼 방향이 드러나는 표현으로 개선한다.
7. 상점 상세 상품 카드의 모바일 밀도를 조정해 같은 화면에서 더 많은 상품을 비교할 수 있게 한다.
8. CSS preload 경고를 별도 낮은 우선순위 정리 과제로 추적한다.
9. 카테고리·상점·공구·장바구니·MY 탭 검증 캡처가 추가될 때마다 이 문서의 탭별 표에 항목을 추가한다.
