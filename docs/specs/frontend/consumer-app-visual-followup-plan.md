# 소비자 앱 육안검증 후속 작업 정리

기준일: 2026-06-17

> **실행 순서 SSOT**: 각 항목의 우선순위, 아토믹 태스크, 정합성 검토, 커밋·배포, 육안검증, 다음 작업 핸드오프는 `docs/plans/PLAN_consumer-app-visual-followup.md`를 따른다. 이 문서는 발견 큐와 상태 기록을 유지한다.

## 1. 목적

소비자 앱 운영 도메인 육안검증 중 발견한 후속 개선 사항을 한 문서에 모아, 홈·카테고리·상점·공구·장바구니·MY 탭의 개선 작업을 탭별로 추적한다.

이 문서는 즉시 구현 문서가 아니라 **육안검증에서 확인된 문제, 판단 근거, 후속 작업 우선순위**를 정리하는 작업 큐다.

## 2. 기록 원칙

- **화면 신뢰도와 구매 판단을 해치는 문제를 우선 기록한다.**
- **기술적 버그 수정 여부와 UX 완성도를 분리해서 판단한다.**
- **운영 데이터 정리 문제와 프론트엔드 표시 개선 문제를 섞지 않는다.**
- **각 항목은 탭, 문제, 영향, 후속 방향, 상태를 함께 남긴다.**

## 3. 상태 기준

| 상태 | 의미 |
| --- | --- |
| `확인 필요` | 캡처나 화면 제보는 있으나 재현 조건을 더 확인해야 함 |
| `작업 후보` | 문제와 방향이 확인됐으나 아직 구현 계획으로 고정하지 않음 |
| `설계 필요` | 별도 선 설계 문서 또는 도메인/API 판단이 필요함 |
| `구현 대기` | 범위와 완료 기준이 충분히 명확해 구현 가능함 |
| `완료` | 구현·검증·배포까지 끝남 |

### W0 lint 기준선

- [x] `useCart.ts`와 `useNotifications.ts`의 `forEach` 콜백은 값을 반환하지 않는 블록 본문을 사용한다.
- [x] 두 훅의 import 정렬을 Biome 기준에 맞춰 파일별 `biome check` 오류를 제거한다.
- [x] 소비자 앱 전체 lint의 기준선은 **오류 0건, 경고 14건**으로 고정한다.
- [x] 잔여 경고는 동작 변경과 섞지 않고 `CONSUMER-LINT-FOLLOWUP`으로 분리해 추적한다.

### 카테고리 탭 현재 판단

- [x] `/category`, `/category?sort=price_asc`, `/category?saleType=group`, `/category?category=orchid&sort=price_asc`에서 URL 기반 탭·정렬 상태가 정상 반영된다.
- [x] 검색 아이콘은 `/search`로 정상 진입한다.
- [x] 콘솔에는 기능 오류가 아니라 CSS preload 경고만 보인다.
- [ ] 공동구매 탭의 의미가 `공동구매 상품 전체`인지 `참여 가능한 공동구매`인지 정책 결정이 필요하다.
- [ ] 계획된 URL·색상·정렬 개선 밖에서는 활성 필터 요약, 빈 상태 맥락, 가격대·배송 방식 필터, 카드 정보 밀도 개선이 다음 후보로 남아 있다.
- [ ] 가격대·배송 방식·판매자 정보 노출은 API 응답 계약 확장이 필요할 수 있어 단순 UI 개선과 분리해 설계한다.

- [x] 상점 상세에서 판매 상품 그리드와 상품 상세 진입이 정상 동작한다.
- [x] 깨진 주소 문자열은 프론트 버그가 아니라 운영 데이터 정리 과제로 분리한다.
- [ ] 상품 0개 상점의 노출 정책은 구매 가능 상점 우선 탐색 관점에서 별도 결정이 필요하다.
- [ ] 정렬 문구는 기능적으로 동작하지만 소비자 이해도 기준으로 더 명확하게 다듬을 수 있다.
- [ ] 상점 상세 상품 카드는 모바일 탐색 밀도 기준으로 추가 개선 여지가 있다.
- [x] CSS preload 경고는 운영 진단 가독성 문제로 기록하되 hydration 오류, 콘솔 error, 화면 깨짐이 없는 한 W11 기능 차단 조건으로 보지 않는다.

### W11 운영 정리 계약

- 깨진 주소 문자열은 `stores/{storeId}.address` 원본 데이터 보정으로만 다룬다.
- 홈·상점 UI는 `주소 미등록`처럼 값이 없을 때의 fallback만 유지하고, 깨진 문자열을 추정 치환하지 않는다.
- 실제 운영 쓰기는 백업, dry-run, 정상 주소 후보, 명시적 승인, 적용 후 공개 화면 재확인이 모두 있을 때만 가능하다.
- 기존 `scripts/ops/repair-mojibake-data.mjs`는 상호명·이름 allowlist 보정 스크립트이므로 주소 보정이 필요하면 주소 전용 옵션 또는 별도 스크립트로 확장한다.
- CSS preload 경고는 브라우저 콘솔의 낮은 우선순위 warning으로 기록한다. `pnpm --filter consumer build` 통과, 화면 렌더 정상, 콘솔 error 0이면 이번 묶음에서는 설정 변경 없이 종결한다.
