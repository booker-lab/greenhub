# 소비자 앱 육안검증 후속 작업 정리

기준일: 2026-06-23

> **실행 순서 SSOT**: 각 묶음의 우선순위, 완료 게이트, 검증·배포 이력은 `docs/plans/PLAN_consumer-app-visual-followup.md`를 따른다. 이 문서는 운영 육안검증 중 발견된 문제와 현재 상태를 추적하는 발견 큐다.

## 1. 목적

소비자 운영 도메인 육안검증 중 발견된 후속 개선 사항을 홈, 카테고리, 상점, 공구, 장바구니, MY 영역별로 추적한다.

## 2. 기록 원칙

- **화면 신뢰도와 구매 판단에 영향을 주는 문제를 우선 기록한다.**
- **기술 버그, UX 완성도, 운영 데이터 정리를 분리한다.**
- **운영 데이터 보정은 백업, dry-run, 명시적 승인 전까지 수행하지 않는다.**
- **완료 상태는 구현, 검증, Preview, Production 승격, 운영 도메인 확인까지 반영한다.**

## 3. 상태 기준

| 상태 | 의미 |

| `확인 필요` | 캡처나 화면 제보는 있으나 재현 조건을 더 확인해야 함 |
| `작업 후보` | 문제와 방향이 확인됐으나 아직 구현 계획으로 고정하지 않음 |

## 7. W11 운영 정리 계약

- 깨진 주소 문자열은 `stores/{storeId}.address` 원본 데이터 보정으로만 다룬다.
- 홈·상점 UI는 `주소 미등록`처럼 값이 없을 때의 fallback만 유지하고, 깨진 문자열을 추정 치환하지 않는다.
- 실제 운영 쓰기는 백업, dry-run, 정상 주소 후보, 명시적 승인, 적용 후 공개 화면 재확인이 모두 있을 때만 가능하다.
- 기존 `scripts/ops/repair-mojibake-data.mjs`는 상호명·이름 allowlist 보정 스크립트이므로 주소 보정이 필요하면 주소 전용 옵션 또는 별도 스크립트로 확장한다.
- CSS preload 경고는 브라우저 콘솔상의 낮은 우선순위 warning으로 기록한다. `pnpm --filter consumer build` 통과, 화면 렌더 정상, 콘솔 error 0이면 기능 차단 조건으로 보지 않는다.

## 10. 남은 작업 후보

1. 소비자앱 사용자 흐름 기준 추가 구현 작업은 남아 있지 않다. W0~W11과 운영주소 보정 쓰기까지 완료됐다.
2. CSS preload 경고: 기능 오류가 없는 낮은 우선순위 운영 진단 경고로 유지한다. 별도 성능 정리 세션이 열리기 전에는 소비자앱 후속 구현 차단 조건으로 보지 않는다.
3. 검증 캡처 추가: 카테고리·상점·공구·장바구니·MY 탭 검증 캡처가 추가될 때마다 단계 표에 항목을 추가한다.
