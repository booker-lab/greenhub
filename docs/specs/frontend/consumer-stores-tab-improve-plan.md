# 소비자 상점 탭 탐색 개선 선 설계

> 작업 ID: `CONSUMER-STORES-TAB-IMPROVE`
> 기준일: 2026-06-17
> 상태: 구현 전 설계

## 목적

소비자 상점 탭을 단순 목록에서 상점 기반 구매 탐색 화면으로 개선한다. 이번 범위는 공개 상점 API 계약을 바꾸지 않고, 프론트엔드 탐색 기능과 표현 계층 구조를 정리하는 데 한정한다.

## 주요 발견 문제와 개선점

| ID | 발견 문제 | 영향 | 개선 방향 |
| --- | --- | --- | --- |
| P1 | `/stores`가 active 상점 전체를 단순 나열한다. | 상점 수가 늘면 소비자가 원하는 판매자를 찾기 어렵다. | 상점명·주소 검색과 가나다순·상품 수순·거점 수순 정렬을 추가한다. |
| P2 | 홈 상점 미리보기와 상점 목록 카드 UI가 중복된다. | 표시 규칙 변경 시 두 화면을 함께 수정해야 한다. | `StoreCard` 표현 컴포넌트로 로고, 상호, 주소, 상품 수, 거점 수 표시를 공유한다. |
| P3 | 공개 상점 조회 훅이 상품 조회 훅 파일에 섞여 있다. | 상품 탐색과 상점 탐색 책임이 섞여 SDD 레이어 경계가 흐려진다. | 공개 상점 조회를 `useStores` 계층으로 분리한다. |
| P4 | 오류 상태와 검색 결과 없음 상태가 충분히 구분되지 않는다. | 사용자가 서버 실패인지 조건 불일치인지 알기 어렵다. | 빈 상점, 검색 결과 없음, 오류 상태를 분리하고 검색 초기화 동작을 제공한다. |
| P5 | 홈 화면은 전체 상품, 공동구매, 상점 API를 각 섹션에서 개별 호출한다. | 초기 화면 로딩 정책이 섹션별로 달라질 수 있다. | 이번 범위에서는 유지하고, 홈 요약 API 또는 캐시 통합은 후속 과제로 분리한다. |
| P6 | 공개 상점 목록 API는 상점마다 상품·거점 수를 별도 조회한다. | 상점 수 증가 시 서버 응답 지연이 커질 수 있다. | 이번 범위에서는 프론트 계약을 유지하고, 집계 필드 또는 count 캐시는 별도 백엔드 과제로 분리한다. |

## 범위

### 이번에 한다

- 상점 목록 검색 입력 추가
- 상점 목록 정렬 선택 추가
- 검색 결과 없음 상태와 초기화 버튼 추가
- 홈 상점 미리보기와 상점 목록 카드 공통화
- 공개 상점 조회 훅 분리
- 기존 상점 상세 상품 링크의 `fromStore`, `storeName` 맥락 유지
- 기존 공개 API 응답 필드만 사용

### 이번에 하지 않는다

- 공개 상점 API 응답 필드 추가
- 상점 위치 지도, 거점 상세 목록, 전화 걸기 기능
- 백엔드 상품·거점 count 집계 구조 변경
- 홈 요약 API 신설
- 운영 Firestore 데이터 정제
- 장바구니·결제 `storeId` 계약 변경

## 정합성 검토

| 축 | 유지해야 할 계약 | 검토 결과 |
| --- | --- | --- |
| 공개 상점 API | `GET /public/stores`는 `items`, `total`을 반환한다. | 검색·정렬은 프론트 로컬 계산으로 처리하므로 API 변경이 없다. |
| 공개 상점 상세 | `GET /public/stores/:storeId`는 `store`, `products`를 반환한다. | 상세 화면은 기존 상품 그리드와 상품 진입 링크를 유지한다. |
| 상품 상세 복귀 | 상점 상세에서 들어간 상품은 `fromStore`, `storeName` 쿼리를 유지한다. | `StoreCard` 공통화는 목록 카드만 다루며 상품 링크 생성 로직은 건드리지 않는다. |
| 장바구니·결제 | 주문 API 경로는 상품 응답의 `storeId`를 신뢰한다. | 상점 목록 검색·정렬은 구매 CTA와 무관하다. |
| 홈 미리보기 | 홈은 active 상점 최대 3개를 읽기 전용으로 보여준다. | 공통 카드 사용 시에도 `limit=3` 표시 정책은 유지한다. |
| 디자인 시스템 | 반복 항목에는 카드 사용이 허용된다. | `StoreCard`는 반복 리스트 항목이므로 카드 사용 기준에 맞다. |
| 파일 크기 | 수정 파일은 500라인 이하를 유지한다. | 신규 컴포넌트·훅 분리로 파일 크기 증가를 분산한다. |

## 아토믹 태스크

| Task | 작업 | 완료 기준 | 검증 |
| --- | --- | --- | --- |
| T1 | `useStores` 훅 분리 | 공개 상점 목록·상세 조회가 상품 훅에서 제거된다. | TypeScript build 통과, `rg "usePublicStore" apps/consumer/src` 결과가 새 훅을 가리킨다. |
| T2 | `StoreCard` 공통 컴포넌트 생성 | 홈 미리보기와 상점 목록이 같은 카드 컴포넌트를 사용한다. | 두 화면에서 로고·상호·주소·상품 수·거점 수가 동일 규칙으로 표시된다. |
| T3 | 상점 목록 검색 상태 추가 | 상점명 또는 주소로 목록을 좁힐 수 있다. | fixture 상점명과 주소 각각으로 검색해 결과가 유지된다. |
| T4 | 상점 목록 정렬 상태 추가 | 가나다순, 상품 수순, 거점 수순을 선택할 수 있다. | 정렬 선택 변경 시 카드 순서가 기대대로 바뀐다. |
| T5 | 결과 없음 상태 분리 | 전체 빈 상태와 검색 결과 없음 상태가 다른 문구와 액션을 가진다. | 검색어 초기화 버튼으로 전체 목록이 복구된다. |
| T6 | 기존 상점 E2E 보강 | 목록 진입, 상세 진입, 상품 링크 계약이 깨지지 않는다. | `consumer-stores.spec.ts`에 검색·정렬 fixture 검증을 추가한다. |
| T7 | 회귀 검증 | 빌드와 라인 수 제한을 통과한다. | `pnpm --filter consumer build`, 라인 수 확인, 가능 시 관련 E2E 실행. |

## W6 추가 결정: 상점 노출 정책과 상세 밀도

> 적용 ID: `C-STORES-04`, `C-STORES-05`, `C-STORES-06`
> 기준일: 2026-06-23

### 상점 목록 노출 정책

- 기본 정렬은 `구매 가능순`으로 표시하며, 실제 기준은 상품 수 내림차순이다.
- 상품 수가 0개인 상점은 모든 정렬에서 구매 가능한 상점 뒤로 보낸다.
- 상품 수가 0개인 상점은 카드에 `준비 중` 배지를 표시하고, 상품 수 문구는 `상품 준비 중`으로 바꾼다.
- 검색어가 있을 때는 검색 결과 안에서 같은 정렬 정책을 유지한다. 검색으로 0개 상점만 남는 경우에도 숨기지 않는다.
- 공개 상점 API 응답 필드만 사용하며, 백엔드 count 계약이나 운영 데이터는 변경하지 않는다.

### 상점 상세 상품 밀도

- 상점 상세 상품 영역은 모바일 375px에서도 2열을 유지한다.
- 상품 카드 사이 간격은 목록 탐색보다 촘촘한 `8px` 기준으로 둔다.
- 데스크톱에서도 상세 상품 그리드는 과도하게 넓어지지 않도록 기존 `sm` 컨테이너와 2열을 유지한다.
- `ProductCard` variant 분리는 W7 범위이므로 이번 변경에서는 상품 카드의 정보 구조를 바꾸지 않는다.

## 실행 순서

1. T1로 데이터 훅 경계를 먼저 분리한다.
2. T2로 카드 표현 중복을 제거한다.
3. T3~T5로 상점 목록 화면 기능을 얹는다.
4. T6~T7로 기존 계약과 새 기능을 함께 검증한다.

## 위험과 완화

| 위험 | 영향 | 완화 |
| --- | --- | --- |
| 검색·정렬이 API 필터처럼 오해될 수 있음 | 운영 데이터가 많아질 때 성능 기대가 어긋난다. | 문서와 코드에서 이번 범위는 클라이언트 필터임을 명확히 둔다. |
| 공통 카드가 홈과 목록의 밀도 차이를 흡수하지 못함 | 홈 미리보기 레이아웃이 답답해질 수 있다. | `variant` 또는 `compact` 속성으로 크기만 조절하고 정보 규칙은 공유한다. |
| 기존 린트 오류가 새 변경 검증을 흐릴 수 있음 | 새 작업 품질 확인이 어려워진다. | 빌드를 필수 검증으로 두고, 린트 실패는 기존 오류와 신규 오류를 분리 기록한다. |
| 공개 상점 count 조회 지연이 UI 개선 후 더 잘 드러남 | 검색 전 초기 로딩이 길어 보인다. | 이번 범위에서는 스켈레톤을 유지하고, 백엔드 집계 개선을 후속으로 둔다. |

## 후속 후보

- 상점 상세에 거점 목록과 배송 가능 정보 표시
- 전화 링크와 지도 열기 추가
- 홈 요약 API 또는 캐시 통합
- 공개 상점 API count 집계 필드 캐시화
- 운영 상점 데이터 정제 자동 점검
