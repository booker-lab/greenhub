# 셀러앱 정산 탭 기능 확장 — Further 세션 확정안 (#CL-56)

> **선설계 문서.** 세션92 `/further` 워크플로로 판매자가 정산 화면에서 답답해하는
> 한 순간을 짚어, **백엔드 신설 없이** 데이터가 이미 있는데 화면이 가리고 있는
> 세 가지 기능을 우선순위·범위로 잠근 결과. 구현은 본 문서 §T 순서대로 별도 착수.
>
> SDD 분리(세션91)·status 필터(세션86)·KST 보정(세션85)으로 정산 탭의
> **표현/품질 레이어는 정돈된 상태** — 본 계획은 그 위의 **기능 부재** 해소.

## 0. 한 줄 요약 (협업용)

판매자가 정산 화면에서 가장 자주 묻는 세 가지 — **"이번 달 얼마 벌었나"·
"내 돈 언제 들어와"·"빠진 정산 없나"** — 에 한눈에 답하도록 화면을 확장한다.
세 기능 모두 **백엔드 데이터는 이미 존재**(`status`/`confirmedAt`/`paidAt`/
`SETTLEMENT_CONFIRM_DELAY_DAYS`)하고, 셀러 화면이 안 보여주고 있을 뿐이다.

## 1. Further 세션 확정 (5건)

| # | 결정 유형 | 확정 |
| :--- | :--- | :--- |
| 1 | 문제·사용자 | 판매자가 정산 화면에서 답답해할 세 순간 — **돈 언제 들어와·이번 달 얼마 벌었나·빠진 정산 찾기** |
| 2 | 범위 | 세 가지 **모두 포함**. 첫 출시 = **이번 달 요약**부터 |
| 3 | 성공 기준 | "이번 달 얼마 벌었나"가 화면 열자마자 답되려면 **빠른 기간 버튼 + 큰 합계 숫자**가 즉시 보여야 함 |
| 4 | 꼭 넣을 것 | 첫 출시에 **빠른 기간 버튼 3개**(이번 주·이번 달·지난달) 필수 |
| 5 | 리스크 완화 | 탭 수를 늘리지 않는다 — 기존 **'일별 요약' 탭을 '요약' 탭으로 확장** |

## 2. 진단 — 백엔드 데이터는 이미 있다 (셀러 화면만 가리고 있음)

`apps/api/src/settlements/settlements.service.ts:46-62`에서 정산 도큐먼트에 이미
저장 중인 필드:

| 필드 | 의미 | 셀러 화면 표시 여부 |
| :--- | :--- | :--- |
| `status` | pending → confirmed → paid (또는 cancelled) | ✅ status 필터(세션86) |
| `settledAt` | 정산 생성 시각 | ✅ 목록 표시 |
| `confirmedAt` | 확정(지급 가능) 시각 | ❌ **미표시** |
| `paidAt` | **지급(입금) 완료 시각** | ❌ **미표시** ← "돈 언제 들어와" 핵심 |
| `SETTLEMENT_CONFIRM_DELAY_DAYS` | confirm 마감까지 일수 | ❌ 미표시 (예정일 계산 가능) |

→ 세 기능 모두 **프론트만 손대면 됨**(예외 = T6 "이번 주" 시작 요일 정책 그레이존, §리스크 참고).

## 3. 하지 않는 것 (범위 밖)

- **백엔드 정산 데이터 모델 신설** — 위 5개 필드로 충분.
- **그래프·차트** — Further §성공 기준에서 "큰 합계 숫자" 채택, 차트 후보(③번 옵션)는 명시적 기각.
- **별도 '요약' 탭 신설** — Further §리스크 결정으로 탭 수 불변(3개 유지), 일별 탭 확장.
- **확정/지급 정책 변경** — 본 문서는 표시 전용. confirm 배치·paid 전이는 그대로.

## 4. 잘 됐다는 기준 (성공 정의)

- 판매자가 정산 탭을 열고 **'요약' 탭 → '이번 달' 버튼 한 번**으로 이번 달 총매출·
  수수료·정산액이 큰 숫자로 보인다.
- '주문별 상세'에서 **각 정산 행에 "입금 완료 YY-MM-DD" 또는 "입금 예정 YY-MM-DD"**
  가 status 배지와 함께 보인다.
- '빠른 정산' 진입점이 있어 **아직 입금 안 된 건(pending·confirmed)** 만 한 화면에서
  확인 가능하다.

## 5. 사용자 여정 (3스텝)

1. 판매자가 정산 탭 진입 → '요약' 탭 기본 선택, 화면 위에 빠른 기간 3버튼.
2. '이번 달' 누름 → 1일~오늘 기간 잡히고 총매출·수수료·정산액 큰 숫자 표시.
3. '주문별 상세'로 이동 → status 배지 옆에 입금 완료일/예정일이 한 줄로 보임.
   pending+confirmed만 보고 싶으면 status 필터(세션86 기존)로 빠른 정산 추림.

## Appendix F. Further 세션 요약 (협업용)

### 세션 주제
셀러앱 정산 탭에서 판매자가 답답해하는 한 순간이 무엇인지부터 짚어, 어떤
기능을 더 만들지 한 걸음씩 맞췄다.

### 함께 확정한 것 (구조)
- 판매자가 가장 자주 묻는 세 가지 — 내 돈 언제 들어와·이번 달 얼마 벌었나·빠진 정산 — 모두 만든다.
- 첫 출시 = **이번 달 얼마 벌었나**.
- 잘 됐다는 기준 = 화면을 열면 **빠른 기간 버튼과 큰 합계 숫자가 즉시 보임**.
- 꼭 넣을 것 = **이번 주·이번 달·지난달 3버튼**.
- 탭 수는 늘리지 않고 **'일별 요약' 탭을 '요약' 탭으로 확장**.

### 나중에 다듬을 것 (UX)
- 기간 라벨 문구("2026-05-01 ~ 오늘 (이번 달)") 표기 통일.
- 입금일 글씨 크기·색(작은 회색 vs status 배지 옆 같은 톤).
- 빠른 정산 진입점 라벨("입금 대기" vs "빠른 정산").

### 아직 열린 질문
- 이번 주 시작 요일 = 월요일 / 일요일 (R1).
- 빠른 정산에서 두 status 동시 조회 = 클라 OR / 백엔드 다중 (D2).

### 다음에 할 일
1. R1 확정 후 T2(util+테스트) 작성.
2. T1(요약 탭 확장) 구현·커밋.
3. T4·T3(입금일 표시) 구현·커밋.
4. D2 확정 후 T5(빠른 정산) 구현.
5. 육안 검증 항목 추가(`pending-visual-verify.md`).

### staff·환자 관점에서 기대되는 변화
판매자가 정산 탭을 열면 **이번 달 매출이 큰 숫자로 즉시 보이고**, 정산 목록의
각 줄에 **언제 입금됐는지/언제 입금 예정인지**가 함께 표시된다. "내 돈
언제 들어와?"라는 문의가 화면 안에서 답된다.
