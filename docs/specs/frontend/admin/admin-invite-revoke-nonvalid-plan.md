# 어드민 초대 사용됨·만료 토큰 취소 정책

> 작업 ID: `ADMIN-INVITE-REVOKE-NONVALID`
> 작성일: 2026-06-04

## 목적

`/admin/invite`는 이미 유효 토큰만 취소할 수 있다. 별도 후보로 남아 있던 사용됨·만료 토큰 취소는 판매자 계정 상태와 감사 로그까지 흔들 수 있으므로, 이번 SDD에서 확장하지 않는 정책으로 확정한다.

## 결정

- 취소 가능한 토큰은 `usedAt`, `revokedAt`이 없고 `expiresAt`이 현재보다 미래인 유효 토큰뿐이다.
- 이미 사용된 토큰은 `409 { reason: 'already_used' }`로 거절하고 `revokedAt`을 쓰지 않는다.
- 이미 취소된 토큰은 `409 { reason: 'already_revoked' }`로 거절하고 기존 취소 기록을 유지한다.
- 만료된 토큰은 `409 { reason: 'expired' }`로 거절하고 `revokedAt`을 쓰지 않는다.
- UI는 `inviteStatus(inv).label === '유효'`인 행에만 취소 버튼을 노출한다.
- 가입 완료 판매자 되돌리기는 초대 토큰 기능이 아니라 사용자·스토어·감사 로그 정책이므로 `ADMIN-INVITE-SELLER-ROLLBACK`에 남긴다.

## 이유

- 사용된 토큰을 취소 상태로 바꾸면 이미 생성된 판매자 계정과 스토어의 법적·운영 상태를 설명하지 못한다.
- 만료 토큰은 이미 가입 불가 상태라 취소 기록을 추가해도 보안 효과가 없다.
- 취소 기록은 "운영자가 아직 유효한 초대를 회수했다"는 감사 이벤트여야 하며, 과거 상태 라벨을 덮어쓰면 CS 원인 추적성이 떨어진다.

## 범위

- 기존 API 계약 유지.
- 사용됨·이미 취소됨·만료 토큰 거절 시 Firestore 쓰기 없음 단위 테스트 보강.
- 백로그와 결정 로그에 정책 종결을 기록한다.

## 제외

- 사용된 토큰에 연결된 판매자 계정 정지·삭제·복구.
- 만료 토큰 재활성화 또는 만료일 연장.
- 초대 상태 shared SSOT 승격.
- 감사 로그 컬렉션 신설.

## 검증

- API 단위 테스트: 유효 토큰만 `revokedAt`·`revokedBy`를 기록한다.
- API 단위 테스트: `already_used`, `already_revoked`, `expired`는 모두 409 reason을 반환하고 문서 쓰기를 하지 않는다.
- 정적 검증: 변경 파일 Biome, API 테스트, API 타입체크와 빌드, `git diff --check`.
