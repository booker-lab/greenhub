# 관리자 정산 500건 하드캡 페이지네이션 SDD

## 1. 문제

`GET /admin/settlements`는 현재 정산 목록을 `settledAt desc` 기준 최대 500건으로만 반환한다. 501번째 이후 데이터는 조용히 누락되어 관리자 화면의 합계, 일괄 지급 대상, 상태별 검토 범위가 실제 데이터와 달라질 수 있다.

## 2. 결정

- API는 `limit`과 `cursor`를 받는다. `limit` 기본값은 100, 최대값은 500이다.
- 응답은 기존 `settlements`와 `total`에 `nextCursor`를 추가한다.
- `nextCursor`가 있으면 프론트는 "더 보기" 버튼을 표시하고, 클릭 시 기존 목록 뒤에 다음 페이지를 이어 붙인다.
- 커서는 `settledAt` 값을 ISO 문자열로 직렬화한다. 현재 운영 인덱스는 `settledAt desc` 계열이 이미 배포되어 있으므로 신규 인덱스를 요구하지 않는 계약을 우선한다.
- 필터(`storeId`, `status`, `from`, `to`)가 바뀌면 첫 페이지부터 다시 조회한다.
- 단건·일괄 지급 성공 후에는 첫 페이지를 재조회한다. 지급 후 기존 추가 페이지 위치를 유지하려고 별도 상태를 추정하지 않는다.

## 3. 레이어 분리

- 백엔드 서비스는 Firestore 쿼리, 커서 파싱, `limit + 1` 조회만 담당한다.
- 프론트 훅은 페이지 상태(`nextCursor`, `loadingMore`)와 append 여부를 담당한다.
- UI 컴포넌트는 로딩 상태와 "더 보기" 노출만 담당하며 커서 구조를 알지 않는다.

## 4. 검증

- API 단위 테스트: 기본 limit+1 조회, `nextCursor`, 필터·cursor·limit 쿼리 적용.
- E2E fixture: 101건 중 첫 100건 조회 후 "더 보기"로 마지막 1건이 이어 붙고 버튼이 사라지는지 검증.
- 정적 검증: API·seller 타입체크, 변경 파일 Biome, 500라인 제한.
