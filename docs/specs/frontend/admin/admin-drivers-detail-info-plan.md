# 관리자 드라이버 상세 정보 보강 계획

> 작성: 2026-06-03 · 범위: `ADMIN-DRIVERS-F4`

## 1. 문제

`/admin/drivers`는 이름, 이메일, 가입일, 승인 상태만 보여 운영자가 실제 연락 가능한 정보와 운행 준비 상태를 빠르게 확인하기 어렵다.

## 2. 데이터 모델 확인

- `users.phone`은 가입·프로필 경로에서 이미 쓰는 공통 사용자 필드다.
- 차량번호, 차종, 보험 정보는 현재 저장·등록 경로가 없다.
- 따라서 이번 범위에서 차량 정보를 새로 수집하거나 임의 생성하지 않는다.

## 3. 결정

- `GET /admin/drivers` 응답에 `phone`을 포함한다.
- 향후 저장될 수 있는 `vehicleType`, `vehicleNumber`는 선택 필드로 통과시키되, 값이 없으면 프론트에서 `차량 정보 미등록`으로 표시한다.
- 검색은 이름·이메일에 더해 전화번호도 포함한다.
- 차량 정보 입력·검증·보험 증명서 관리는 별도 SDD로 분리한다.

## 4. 구현 작업

- API `DriverRow`에 `phone`, `vehicleType`, `vehicleNumber`를 추가하고 비밀번호 해시는 계속 제거한다.
- seller `AdminDriver` 타입에 동일 필드를 추가한다.
- 드라이버 카드에 `연락처 ...`, `차량 ...` 행을 추가한다.
- E2E fixture에 전화번호와 차량 정보 경계를 추가해 데스크톱·모바일 표시와 전화번호 검색을 검증한다.

## 5. 검증

- API 단위 테스트에서 드라이버 응답이 `phone`과 선택 차량 필드를 포함하고 `passwordHash`를 제외함을 확인한다.
- `admin-drivers-status-filter.spec.ts`에서 전화번호 검색, 차량 정보 표시, 미등록 표시, 모바일 가로 넘침 0을 확인한다.
- 변경 파일 Biome, API·seller 타입체크, API·seller 빌드를 통과시킨다.
