# 소비자 홈 공동구매 개선 선 설계

기준일: 2026-06-17

## 1. 목적

소비자 홈 탭에서 공동구매 미리보기의 화면 신뢰도를 회복하고, 사용자가 홈에서 공동구매 참여 여부를 빠르게 판단할 수 있도록 진행 정보를 강화한다.

이번 설계는 구현 전에 발견 문제, 개선 방향, 아토믹 태스크, 정합성 검토를 먼저 고정한다.

## 2. 주요 발견 문제점

| ID | 문제 | 영향 | 근거 |
| --- | --- | --- | --- |
| P1 | 공동구매 미리보기의 `next/image fill` 부모 영역이 고정되지 않아 이미지가 홈 전체를 덮을 수 있음 | 홈 섹션 경계가 무너지고 상점·상품 정보 가독성이 떨어짐 | 브라우저 확인 시 공동구매 이미지가 카드 영역 밖으로 확장됨 |
| P2 | 공동구매 미리보기 정보가 현재 수량과 목표 수량 중심이라 참여 판단 정보가 부족함 | 사용자가 “지금 참여해야 하는 이유”를 홈에서 파악하기 어려움 | 기존 카드가 `0/50개` 수준의 정보만 제공 |
| P3 | 마감 시간이 지난 공동구매 데이터가 남아 있을 때 소비자 화면 문구가 모호할 수 있음 | 실제 모집 가능 여부와 화면 상태가 어긋나 신뢰도 하락 | 실데이터에서 마감 시간이 지난 공동구매가 홈에 노출됨 |
| P4 | 홈 데이터 호출이 전체 상품, 공동구매, 상점으로 분산되어 있음 | 로딩·오류·빈 상태 정책이 섹션마다 달라질 수 있음 | `useProducts`, `usePublicStores`가 홈 하위 컴포넌트에서 각각 호출됨 |
| P5 | 상점 공개 데이터에 깨진 주소 문자열이 섞여 있음 | 홈 상점 미리보기의 신뢰도가 낮아짐 | 브라우저 확인 시 테스트 상점 주소가 깨진 문자로 표시됨 |

## 3. 개선 원칙

- **홈 화면 신뢰 회복을 최우선으로 한다.**
- **공동구매 미리보기는 “이미지, 남은 시간, 남은 수량”을 한 카드 안에서 판단할 수 있어야 한다.**
- **소비자 홈의 구매 흐름은 이번 작업에서 바꾸지 않는다.**
- **데이터 정합성 문제는 화면 보정과 운영 데이터 정리를 분리한다.**

## 4. 이번 범위

### 포함

- 공동구매 미리보기 이미지가 카드 영역 안에만 표시되도록 레이아웃 고정
- 공동구매 미리보기 카드에 마감 상태, 현재 수량, 목표 수량, 남은 수량 표시
- 목표 수량을 이미 채운 공동구매는 홈의 진행 중 미리보기에서 제외
- 마감 시간이 없거나 해석할 수 없는 공동구매는 화면이 깨지지 않도록 기본 상태 표시
- 선 설계 문서와 결정 로그 갱신

### 제외

- 상품 상세, 장바구니, 결제 흐름 변경
- 공동구매 상태 전환 API 변경
- 상점 데이터 정제 스크립트 실행
- 홈 전체 데이터 조합 API 신설

## 5. 아토믹 태스크

| 순서 | 태스크 | 완료 기준 | 정합성 확인 |
| --- | --- | --- | --- |
| T1 | 공동구매 이미지 부모 영역에 명시적 기준 좌표 추가 | 공동구매 이미지가 카드 영역 밖으로 확장되지 않음 | 브라우저에서 이미지 실제 크기가 카드 크기와 일치 |
| T2 | 공동구매 미리보기 카드를 별도 내부 컴포넌트로 분리 | 이미지, 이름, 마감 상태, 수량 문구가 한 컴포넌트에서 관리됨 | 홈 전체 상품 카드와 링크 흐름이 변하지 않음 |
| T3 | 마감 라벨 계산 함수 추가 | 미래 마감은 분·시간·일 단위로 표시되고, 값이 없으면 `모집 중` 표시 | 유효하지 않은 날짜에서도 렌더링 실패가 없음 |
| T4 | 남은 수량 계산 추가 | `현재/목표개 · N개 더 필요` 문구 표시 | 남은 수량은 음수가 되지 않음 |
| T5 | 진행 중 공동구매 필터 기준 정리 | 목표 수량 달성 상품은 홈 미리보기에서 제외 | 전체 공동구매 페이지의 목록 정책은 변경하지 않음 |
| T6 | 스펙 문서 갱신 | 발견 문제, 개선 원칙, 태스크, 정합성 검토가 문서에 남음 | 문서가 구현 변경보다 먼저 판단 근거를 제공 |
| T7 | 브라우저 홈 확인 | 홈에서 공동구매 카드가 정상 표시됨 | 콘솔 오류가 없고 하단 내비게이션이 유지됨 |
| T8 | 빌드·린트 결과 기록 | 검증 결과와 남은 외부 이슈를 구분해 기록 | 실패가 이번 변경 때문인지 기존 이슈인지 분리 |

## 6. 정합성 검토

### 화면 정합성

- 공동구매 미리보기 이미지는 카드 내부에만 표시되어야 한다.
- 공동구매 카드의 링크는 기존처럼 상품 상세로 이동해야 한다.
- 홈의 하단 내비게이션, 상점 미리보기, 전체 상품 목록은 기존 위치를 유지해야 한다.
- 작은 화면에서도 남은 수량 문구가 카드 밖으로 넘치지 않아야 한다.

### 데이터 정합성

- `groupSummary.currentQuantity`, `groupSummary.targetQuantity`가 있을 때만 수량 판단 문구를 강화한다.
- `targetQuantity`가 없거나 0이면 수량 문구는 `모집 중`으로 fallback한다.
- 이미 목표 수량을 채운 상품은 홈의 진행 중 미리보기에서 제외한다.
- 마감 시간이 지났지만 백엔드 상태가 정리되지 않은 데이터는 별도 운영 정리 대상으로 남긴다.

### 계층 정합성

- 이번 작업은 소비자 홈 프론트엔드 표시 계층에 한정한다.
- 공동구매 모집 확정, 취소, 환불 같은 비즈니스 상태 전환은 API·도메인 레이어 책임으로 남긴다.
- 화면에서 임의로 주문 가능 여부를 확정하지 않는다.

### 문서 정합성

- 신규 기능성 개선은 `docs/specs/frontend/` 아래 선 설계 문서에 먼저 남긴다.
- 설계 판단은 `docs/CRITICAL_LOGIC.md`에 결정 로그로 남긴다.
- 기존 소비자 상점 Phase 2 문서와 충돌하지 않도록 상점 데이터 정제는 이번 범위에서 제외한다.

## 7. 검증 계획

- `pnpm --filter consumer build`
- `pnpm --filter consumer lint`
- 로컬 브라우저에서 홈 탭 확인
- 공동구매 이미지 실제 표시 영역 확인
- 공동구매 미리보기 텍스트 확인
- 기존 전체 상품 카드와 하단 내비게이션 유지 확인

## 8. 남은 이슈

- 소비자 앱 전체 lint에는 기존 `<img>`, 배열 index key, non-null assertion, `forEach` callback return 문제가 남아 있다.
- `/category` 페이지는 `useSearchParams` Suspense 경계 이슈로 빌드가 막힐 수 있다.
- 테스트 상점 주소의 깨진 문자는 프론트엔드 표시 개선이 아니라 운영 데이터 정리 과제로 분리해야 한다.
- 홈 데이터 호출 통합은 별도 설계로 분리하는 것이 안전하다.

## 9. 구현 기록

- [x] 공동구매 미리보기 카드의 `next/image fill` 부모 영역에 `position: relative`, `width: 100%`, `aspect-ratio`를 함께 고정했다.
- [x] 공동구매 미리보기 카드에서 마감 라벨과 `현재/목표개 · N개 더 필요` 문구를 표시한다.
- [x] `targetQuantity > 0`인 데이터에서만 목표 달성 제외 필터를 적용하고, 목표 수량이 없거나 0인 데이터는 `모집 중` fallback으로 표시한다.
- [x] 작은 화면에서 이름과 수량 문구가 카드 밖으로 밀리지 않도록 카드 폭과 텍스트 줄바꿈 기준을 보강했다.
