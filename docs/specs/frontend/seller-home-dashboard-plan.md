# 셀러앱 홈 대시보드 + 준비 물량 재구성 — 아토믹 태스크 플랜

> 작성: 2026-05-18 (세션38)
> 근거: 셀러앱 전체 페이지 UX 감사 + 네이버 스마트스토어센터 대시보드 벤치마크
> 원칙: **로직 불변** — 기존 훅/API/비즈니스 로직은 변경하지 않고 UI·내비게이션 레이어만 손댐.
> 진행: **아토믹 태스크 단위** — 한 태스크 = 한 커밋. 각 태스크 끝에 타입체크 통과 후 다음 진행.

---

## 배경

세션36 seller 프론트 리팩토링(#CL-32)은 **코드 구조** 정비였고 비주얼·내비게이션
UX는 감사한 적이 없다. 세션38 전체 페이지 감사 + 사용자 논의에서 세 문제가 확인됐다.

1. **홈(`/`)이 고아 페이지** — `BottomNav` 탭은 주문·상품·정산·거점·설정 5개뿐이고
   홈 진입점이 없다. 다른 페이지로 이동하면 홈 대시보드로 돌아올 길이 없다.
2. **홈 대시보드 정보 밀도가 얕음** — 메트릭 카드 4개뿐. 영역별 처리 대기 현황과
   "오늘 할 일"이 안 보인다.
3. **준비 물량 파악이 주문 건별로 흩어짐** — 셀러가 물건을 준비하려면 주문을 하나씩
   열어 봐야 한다. "장미 12송이 / 튤립 8송이"처럼 상품별로 합산된 픽업 리스트가 없다.

### 네이버 스마트스토어센터 벤치마크 — 적용 범위

| 네이버 요소 | 그린허브 적용 | 비고 |
|------------|--------------|------|
| 좌측 사이드바 풀 메뉴 | ❌ 미적용 | BottomNav와 중복. 홈 진입점만 추가 |
| 할 일 | ✅ 오늘 할 일 카드 | 명령형 체크리스트 |
| 판매 관리 파이프라인 | ✅ 주문 처리 현황 카드 | groupCounts가 처리필요→대기→배송→완료 순 |
| 정산 관리 카드 | ✅ 정산 현황 카드 | `/settlements/summary` 활용 |
| 상품 관리 카드 | ✅ 상품 현황 카드 | "품절"은 그린허브에 재고 개념 없어 비활성만 |
| 취소·반품·교환 / 판매 지연 / 리뷰 / 문의 | ❌ 미적용 | 해당 기능 자체가 없음 |

## 설계 결정

### D1. 홈 진입점 — PageHeader 중앙 홈 아이콘

`PageHeader`를 3분할한다. 홈 아이콘은 `position: absolute`로 화면 정중앙 고정 —
좌/우 콘텐츠 길이와 무관하게 위치 불변, 뒤로가기 버튼과 겹치지 않는다.

```
[← 뒤로]  제목            [🏠]            우측(실시간 연결 등)
  좌측 zone               중앙(고정)        우측 zone
```

- 홈 아이콘 탭 → `/` 이동. `usePathname()`으로 현재 경로가 `/`이면 숨김.

### D2. 홈 = "오늘 할 일" + 현황 카드 3개

데스크톱 다단 그리드인 네이버 레이아웃을 480px 모바일 PWA에 맞춰 세로 스택으로 변환.

```
┌─────────────────────────────────┐
│ 홈                  ● 실시간 연결 │  ← PageShell + PageHeader 적용
├─────────────────────────────────┤
│ ☀️ 오늘 할 일                     │  ← 최상단 — 셀러가 제일 먼저 봄
│ 🔴 신규 주문 3건 처리하기      → │     건수 0이면 줄 숨김
│ 🔴 발송 지연 1건 확인          → │     전부 0이면 "모두 마쳤어요 🎉"
│ ⚠️ 비활성 상품 1건 점검        → │
├─────────────────────────────────┤
│ 주문 처리 현황            더보기 > │
│ ┌───┐→┌───┐→┌───┐→┌───┐         │  ← 파이프라인 4칸 (탭 → /orders?tab=X)
│ │처리│ │대기│ │배송│ │완료│        │
│ │필요│ │ 중 │ │ 중 │ │   │        │
│ │ 3 │ │ 0 │ │ 1 │ │12 │         │
│ └───┘ └───┘ └───┘ └───┘         │
│ 취소 0건                          │
├─────────────────────────────────┤
│ 정산 현황                 더보기 > │
│ 오늘 정산 예정        142,000원   │
├─────────────────────────────────┤
│ 상품 현황                 더보기 > │
│ 판매 중 8  ·  비활성 2            │
└─────────────────────────────────┘
   [주문][상품][정산][준비][설정]      ← BottomNav (D4 참조)
```

**오늘 할 일 카드** — 현황 카드가 "상태를 본다(browse)"라면 할 일은 "지금 해라
(action)". 명령형 한 줄 + 그 작업 화면으로 직행. 각 줄은 건수 > 0일 때만 렌더,
전부 0이면 완료 메시지. 3개 항목 모두 홈이 이미 로드하는 데이터로 계산 — 신규
백엔드 불필요:

| 할 일 | 계산 | 탭 이동 |
|-------|------|---------|
| 신규 주문 처리 | `groupCounts.ACTION_REQUIRED` | `/orders?tab=ACTION_REQUIRED` |
| 발송 지연 | 배송예정일 < 오늘 & 미발송 주문 수 | `/prep` (준비 물량 탭 지연 섹션) |
| 비활성 상품 점검 | `products.filter(!isActive)` | `/products` (비활성 필터) |

### D3. 홈 카드 기준 — "변하는 현황이 있는 영역만"

홈 카드는 셀러가 수시로 확인할 **변하는 현황 숫자**가 있는 영역만 둔다. 주문(처리
대기)·정산(정산 예정 금액)·상품(판매 중 수)이 해당.

**설정·거점은 홈 카드에서 제외.** 배송비·배송 슬롯·사업자 프로필, 그리고 거점
관리는 한 번 맞춰두는 **구성(configuration)**이지 변화하는 "현황"이 아니다 — 카드로
만들면 빈 껍데기가 된다. 둘 다 D4의 설정 탭이 진입구.

### D4. 네비게이션 재구성 — 거점 → 설정, 준비 물량 탭 신설

`BottomNav` 5탭을 재편한다.

```
변경 전:  주문 · 상품 · 정산 · 거점 · 설정
변경 후:  주문 · 상품 · 정산 · 준비 · 설정
```

- **거점 탭 제거** — 거점 관리(`/hubs` 이하 전체)는 구성 작업이므로 D3 원칙대로
  설정 하위로 이동. 설정 페이지에 "거점 관리" 진입 항목 추가.
- **준비 탭 신설** — `/prep` 라우트. 준비 물량 집계 화면(D5). 셀러의 매일 핵심
  업무라 하단 고정 노출.
- 주문 탭과 준비 탭은 역할이 갈린다 — **주문 = 건별 처리**, **준비 = 상품별 집계**.

### D5. 준비 물량 탭 — 주문을 상품별로 집계

주문 1건 = 상품 1개(`order.productId` + `order.quantity`, line-items 배열 없음)
구조라, **`productId`별로 `quantity`를 합산**하면 픽업 리스트가 된다. 상품명은
`useStoreProducts`로 `productId` → `product.name` 조인.

```
┌─────────────────────────────────┐
│ ← 준비 물량              [🏠]     │
├─────────────────────────────────┤
│ 오늘 준비 물량 (5/18)             │
│ 장미 다발 (레드)            12개  │
│ 튤립 (화이트)                8개  │
│ 프리지아                     5개  │
│ ───────────────────────────────  │
│ 3개 상품 · 총 25개                │
├─────────────────────────────────┤
│ 🔴 발송 지연 (배송일 경과)        │  ← 지연분 있을 때만
│ 장미 다발 (레드)   2개  주문 보기> │
└─────────────────────────────────┘
```

- **집계 대상**: 미발송 상태 = `ACCEPTED` · `CONFIRMED` · `PREPARING`.
- **오늘분 / 지연분 분리** (사용자 결정):
  - 배송예정일 **= 오늘** → "오늘 준비 물량" 집계표.
  - 배송예정일 **< 오늘** → "발송 지연" 섹션 (홈 오늘 할 일과 연동).
  - 배송예정일 **> 오늘** → 표시 안 함 (아직 할 일 아님).
- **"특상/상" 등급**: 그린허브 데이터 모델에 등급 필드는 없으나, 셀러가 등급별로
  **상품을 따로 등록**했으면 `productId`가 달라 자동으로 분리 집계된다. 상품(등록
  단위)이 곧 준비 단위.
- 상품명 옆 색상·줄기 표기는 동명 상품 구분용 — `product.selection` 활용, 선택 적용.

> 구현 확인: 배송예정일은 일반 주문 `requestedDeliveryDate` 기준. 공동구매 주문은
> 배송일이 `groupProductConfig.groupDeliveryDate`(별도 문서)에 있어 포함하려면
> 추가 fetch가 필요. 1차 구현 범위(일반 주문만 vs 공동구매 포함)는 T6 착수 시 확정.

### D6. 폐기 — 상단 아이콘 그리드

초안의 "전체 메뉴 아이콘 그리드"는 BottomNav와 중복이라 폐기. 심화 페이지는 각
부모 페이지에 진입 버튼이 이미 있어 고아가 아니다.

## 데이터 소스

| 카드/탭 | 데이터 | 호출 |
|---------|--------|------|
| 오늘 할 일 | `useOrders`(groupCounts·orders) + `useStoreProducts` | 기존 |
| 주문 처리 현황 카드 | `useOrders` → `groupCounts` | 기존 (Firestore 실시간) |
| 정산 현황 카드 | `GET /stores/{id}/settlements/summary?date={today}` | 신규 홈 fetch |
| 상품 현황 카드 | `useStoreProducts` → `products` | 기존 (Firestore 실시간) |
| 준비 물량 탭 | `useOrders` + `useStoreProducts` (공동구매 시 `groupProductConfig`) | 기존 |

정산 summary는 REST 1회 호출. 홈 전용 경량 훅 `useDashboardSummary` 신설 권장
(`apiJson` 사용 — #CL-32 기준, raw `fetch` 금지).

### 하루 물량 초과 — 구조적으로 불가능 (메모)

`dailyCaps`(배송 슬롯)가 주문 생성 시 Firestore 트랜잭션으로 `usedSlots < totalCap`
을 검증한다(orders 스펙 §6). 날짜별 `totalCap`을 넘으면 그 날짜는 주문이 막힌다.
따라서 "오늘 준비 물량"은 항상 셀러가 `/settings/daily-caps`에서 정한 cap 이내 —
초과 케이스 별도 처리 불필요. 셀러의 물량 조절 레버는 슬롯 달력이다.
