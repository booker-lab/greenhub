## 1. 문제 (한 줄)

> 사장님이 매일 쓰는 셀러 주문 관리 화면은 "들어온 주문을 처리"하는 흐름은 잘 되어 있지만, **발송한 뒤에 일어나는 일**(송장 추적·지연 인지·다건 처리)을 사장님이 화면에서 거의 보지 못해 손님 문의와 정산 지연으로 이어진다.

**현재 화면이 잘 되는 것**
- 일반/공동구매 토글, 날짜 프리셋 필터, 상태 그룹 탭, 배송 중 서브필터
- 주문 상세에서 준비 시작·택배 발송 완료·강제 취소 액션

**비어 있는 것**
- 택배 발송 완료를 누르면 바로 `DELIVERED`로 점프 — **송장번호 칸이 없음**
- 배송 예정일 지난 "지연" 그룹은 보이지만, 새 주문·지연 주문을 **사장님에게 먼저 띄워주는 장치**가 없음
- 준비·발송을 **건 하나씩만** 처리 가능

## §A. 걸음 ① — 택배 송장번호 저장·표시

### A.1 이번 차수 범위

**하는 것**
- 택배(`deliveryMethod === 'parcel'`) 주문에서 사장님이 택배사·송장번호를 입력해 저장
- 저장된 송장번호가 사장님 주문 상세와 손님 주문 상세에 보임

**하지 않는 것 (이번 차수)**
- 앱 안 "배송조회" 버튼·외부 링크 자동 생성
- 택배사 API 실시간 상태 표시(집화/이동중/배달완료 등) — 후속 차수
- 한 주문에 송장번호 여러 개(분할 발송) — 후속 차수 후보

### A.2 잘 됐다는 기준

- 택배 주문은 송장 입력 없이는 "발송 완료"로 못 넘어감
- 손님이 자기 주문 상세를 열면 사장님이 입력한 택배사명·송장번호를 본다

### A.3 꼭 넣을 것 (Must)

| ID | 항목 | 비고 |
| :--- | :--- | :--- |
| A-M1 | "택배 발송 완료" 버튼은 송장 입력 폼을 먼저 띄움 | 현 `handleShipParcel`을 모달·인라인 폼으로 교체 |
| A-M2 | 택배사: 미리 정한 목록(우체국·CJ대한통운·한진·롯데 등) + '기타' 자유 입력 | 운영진이 목록을 관리할 위치는 미정(아래 §A.5) |
| A-M3 | 송장번호 검사: 목록 택배사는 택배사별 자릿수 규칙, '기타'는 공백만 막음 | 목록 택배사 자릿수 표는 후속 |
| A-M4 | 택배사·송장번호 둘 다 채워야 발송 처리(`DELIVERED`) | 백엔드 가드도 동시에 추가 검토 |

### A.4 나중에 다듬을 것 (Polish 후보)

- 손님 화면 노출 모양 — 텍스트만 / 복사 버튼 / 택배사별 조회 링크
- 사장님이 한 번 저장한 송장번호를 다시 고치는 규칙(오타 대응)
- 송장 입력 폼에서 택배사 자동 추정(번호 앞자리·자릿수)

### A.5 아직 열린 질문

1. 목록 택배사를 어디서 관리할지 — 코드 상수(`_constants.ts`) vs 어드민 화면
2. 같은 주문에 여러 송장(분할 발송)이 필요한 사례가 운영에 있는지
3. 손님 화면에 노출되는 시점 — 사장님이 저장한 즉시 vs 손님에게 푸시 알림까지

### A.6 다음 단계

- grill-me로 위 §A.1~A.5를 심문 → 빈 곳·맹점 보완 → 본 파일 §A에 추가
- 보완 끝나면 `docs/plans/PLAN_seller-orders-tracking.md` 단독 계획서로 분리

## §B. 걸음 ② — 지연·신규 주문 사장님 알림

### B.1 의도(Further 미착수)

- 배송 예정일이 지난 "지연" 주문, 또는 새로 들어온 `ACTION_REQUIRED` 주문을 **사장님에게 화면을 열기 전부터** 알려준다.
- 현 구조에서 `groupCounts[ACTION_REQUIRED]` 배지는 있지만, 화면을 안 열면 모름.

### B.2 2026-05-29 1차 구현 범위

**결정**: 푸시 알림은 별도 차수로 남기고, 이번 차수는 `/orders` 진입 즉시 보이는 **화면 내 우선 알림 배너**로 한정한다.

- `ACTION_REQUIRED` 주문이 있으면 처리 필요 건수를 배너에 표시하고, 버튼으로 처리 필요 탭에 바로 이동한다.
- 배송 예정일이 지난 활성 주문이 있으면 지연 건수를 배너에 표시하고, 가장 먼저 지연이 있는 탭으로 이동한다.
- 기본 날짜 필터가 `이번 주`여도 지연 주문은 날짜 필터에 밀려 숨지 않고 `지연` 그룹으로 먼저 노출한다.
- 공동구매 주문은 기존 `groupProductConfig.groupDeliveryDate` 조인 결과를 기준으로 지연 여부를 판단한다.
- 공동구매 지연 배너 계산은 현재 선택 탭이 아니라 공구 전체 주문의 `productId`를 조인 대상으로 삼아, 탭 밖 지연 주문도 누락하지 않는다.

**제외**: 브라우저 푸시, 카카오/문자 알림, 새 주문 실시간 토스트, 알림 읽음 상태 저장은 이번 차수에서 제외한다.

### B.3 다음 단계

- Further 별도 차수 — 범위(앱 내 표시만 / 푸시까지)·성공 기준·꼭 넣을 것을 새로 잡는다.

## §C. 걸음 ③ — 여러 주문 일괄 처리

### C.1 의도

- 같은 날짜·같은 상품 묶음 주문을 **여러 건 골라서** "준비 시작" 또는 "택배 발송 완료"를 한 번에 처리.
- 바쁜 날 클릭 횟수와 작업 누락을 줄임.

### C.2 2026-05-29 1차 구현 범위

**결정**: 이번 차수는 송장번호와 충돌하지 않는 **일괄 준비 시작**으로 한정한다.

- 대상 상태는 `ACCEPTED`·`CONFIRMED` 주문만 허용한다.
- 주문 목록 카드에 준비 가능 주문 선택 체크박스를 표시한다.
- 목록 상단에 준비 가능 건수, 선택 건수, 전체 선택, 선택 해제, `준비 시작` 액션 바를 표시한다.
- `준비 시작` 실행 전 확인 모달을 띄우고, 선택 주문 각각에 기존 `PATCH /stores/:storeId/orders/:orderId/status`를 호출한다.
- 성공 건은 선택 상태에서 제거하고, 일부 실패 시 성공/실패 건수를 알림으로 표시한다.
- 상태 전이 비즈니스 규칙은 기존 API에 남기고, 화면은 선택과 요청 오케스트레이션만 담당한다.

**제외**:
- 택배 발송 일괄 처리. 송장번호가 주문별로 다르므로 별도 UX가 필요하다.
- 준비 시간 일괄 입력. 기존 상세 폼의 `preparedAt` 보정은 단건 상세 흐름에 유지한다.
- 백엔드 일괄 API. 운영 규모가 커지거나 부분 실패 감사 로그가 필요해질 때 별도 SDD로 승격한다.

### C.3 다음 단계

- 택배 발송 일괄 처리 — 송장번호 입력 방식(주문별 입력표, CSV, 스캔 흐름)을 별도 Further 차수에서 확정한다.
- 백엔드 일괄 API — 요청 수가 많아질 경우 `bulk-prepare` 계약과 감사 로그를 별도 계획서로 분리한다.

### C.4 2026-05-29 2차 구현 범위

**결정**: 택배 발송 일괄 처리는 CSV·스캔 흐름 없이, 화면에서 선택한 `PREPARING` 택배 주문마다 택배사와 운송장번호를 입력하는 모달로 먼저 구현한다.

- 대상 상태는 `PREPARING`이고 `deliveryMethod === 'parcel'`인 주문만 허용한다.
- `대기 중` 탭에서 택배 발송 가능 주문 체크박스를 표시한다.
- 목록 상단 액션 바는 `택배 발송 가능 N건`, 선택 건수, 전체 선택, 선택 해제, `택배 발송` 버튼을 표시한다.
- `택배 발송` 실행 전 주문별 입력 모달을 띄우고, 각 행에서 택배사·운송장번호를 입력한다.
- 택배사는 단건 발송과 같은 목록을 사용하고, `기타`는 주문별 직접 입력을 요구한다.
- 운송장번호는 공백 제거 후 3자 이상이어야 하며, 모든 선택 주문이 유효해야 실행 버튼을 활성화한다.
- 실행은 기존 단건 `PATCH /stores/:storeId/orders/:orderId/status`를 주문별로 호출해 API의 parcel 가드를 그대로 사용한다.
- 성공 건은 선택 상태에서 제거하고, 일부 실패 시 성공/실패 건수를 알림으로 표시한다.

**제외**:
- CSV 업로드, 바코드 스캔, 택배사별 상세 자릿수 검증.
- 백엔드 일괄 API와 감사 로그.
- 이미 발송된 송장번호 수정.

## 2026-05-29 짠A 구현 확정

- **결정**: 택배 `PREPARING → DELIVERED` 전환은 택배사와 운송장번호를 필수로 받는다.
- **택배사 입력**: 판매자 화면은 `CJ대한통운`, `우체국택배`, `한진택배`, `롯데택배`, `로젠택배`, `기타` 목록을 제공하고, `기타` 선택 시 직접 입력을 요구한다.
- **검증**: 운송장번호는 공백 제거 후 3자 이상이어야 하며, 백엔드는 같은 필수값 검증을 수행해 UI 우회 호출을 차단한다.
- **노출**: 저장된 택배사와 운송장번호는 판매자 주문 상세와 소비자 주문 상세에 표시한다.
