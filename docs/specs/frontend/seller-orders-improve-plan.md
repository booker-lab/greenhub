## 1. 문제 (한 줄)

> 사장님이 매일 쓰는 셀러 주문 관리 화면은 "들어온 주문을 처리"하는 흐름은 잘 되어 있지만, **발송한 뒤에 일어나는 일**(송장 추적·지연 인지·다건 처리)을 사장님이 화면에서 거의 보지 못해 손님 문의와 정산 지연으로 이어진다.

**현재 화면이 잘 되는 것**
- 일반/공동구매 토글, 날짜 프리셋 필터, 상태 그룹 탭, 배송 중 서브필터
- 주문 상세에서 준비 시작·택배 발송 완료·강제 취소 액션

**비어 있는 것**
- 택배 발송 완료를 누르면 바로 `DELIVERED`로 점프 — **송장번호 칸이 없음**
- 배송 예정일 지난 "지연" 그룹은 보이지만, 새 주문·지연 주문을 **사장님에게 먼저 띄워주는 장치**가 없음
- 준비·발송을 **건 하나씩만** 처리 가능

## §A. 걸음 ① — 택배 송장번호 저장·표시

### A.1 이번 차수 범위

**하는 것**
- 택배(`deliveryMethod === 'parcel'`) 주문에서 사장님이 택배사·송장번호를 입력해 저장
- 저장된 송장번호가 사장님 주문 상세와 손님 주문 상세에 보임

**하지 않는 것 (이번 차수)**
- 앱 안 "배송조회" 버튼·외부 링크 자동 생성
- 택배사 API 실시간 상태 표시(집화/이동중/배달완료 등) — 후속 차수
- 한 주문에 송장번호 여러 개(분할 발송) — 후속 차수 후보

### A.2 잘 됐다는 기준

- 택배 주문은 송장 입력 없이는 "발송 완료"로 못 넘어감
- 손님이 자기 주문 상세를 열면 사장님이 입력한 택배사명·송장번호를 본다

### A.3 꼭 넣을 것 (Must)

| ID | 항목 | 비고 |
| :--- | :--- | :--- |
| A-M1 | "택배 발송 완료" 버튼은 송장 입력 폼을 먼저 띄움 | 현 `handleShipParcel`을 모달·인라인 폼으로 교체 |
| A-M2 | 택배사: 미리 정한 목록(우체국·CJ대한통운·한진·롯데 등) + '기타' 자유 입력 | 운영진이 목록을 관리할 위치는 미정(아래 §A.5) |
| A-M3 | 송장번호 검사: 목록 택배사는 택배사별 자릿수 규칙, '기타'는 공백만 막음 | 목록 택배사 자릿수 표는 후속 |
| A-M4 | 택배사·송장번호 둘 다 채워야 발송 처리(`DELIVERED`) | 백엔드 가드도 동시에 추가 검토 |

### A.4 나중에 다듬을 것 (Polish 후보)

- 손님 화면 노출 모양 — 텍스트만 / 복사 버튼 / 택배사별 조회 링크
- 사장님이 한 번 저장한 송장번호를 다시 고치는 규칙(오타 대응)
- 송장 입력 폼에서 택배사 자동 추정(번호 앞자리·자릿수)

### A.5 아직 열린 질문

1. 목록 택배사를 어디서 관리할지 — 코드 상수(`_constants.ts`) vs 어드민 화면
2. 같은 주문에 여러 송장(분할 발송)이 필요한 사례가 운영에 있는지
3. 손님 화면에 노출되는 시점 — 사장님이 저장한 즉시 vs 손님에게 푸시 알림까지

### A.6 다음 단계

- grill-me로 위 §A.1~A.5를 심문 → 빈 곳·맹점 보완 → 본 파일 §A에 추가
- 보완 끝나면 `docs/plans/PLAN_seller-orders-tracking.md` 단독 계획서로 분리

## §B. 걸음 ② — 지연·신규 주문 사장님 알림

### B.1 의도(Further 미착수)

- 배송 예정일이 지난 "지연" 주문, 또는 새로 들어온 `ACTION_REQUIRED` 주문을 **사장님에게 화면을 열기 전부터** 알려준다.
- 현 구조에서 `groupCounts[ACTION_REQUIRED]` 배지는 있지만, 화면을 안 열면 모름.

### B.2 다음 단계

- Further 별도 차수 — 범위(앱 내 표시만 / 푸시까지)·성공 기준·꼭 넣을 것을 새로 잡는다.
