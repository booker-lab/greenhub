# 소비자 카테고리 탐색 완성형 선설계

> 기준일: 2026-06-17
> 범위: `apps/consumer` 카테고리 화면

## 목적

소비자 카테고리 화면을 단순 상품 목록에서 공유 가능한 탐색 화면으로 확장한다. 사용자는 카테고리, 공동구매, 색상, 정렬 조건을 조합하고 상품 상세를 다녀온 뒤에도 같은 조건으로 목록을 이어서 볼 수 있어야 한다.

## 주요 발견 문제

| ID | 문제 | 근거 | 영향 |
| --- | --- | --- | --- |
| F1 | 판매 방식 타입 불일치 | 소비자 훅은 `group | direct`, 공유 타입과 API는 `normal | group` | 일반판매 필터 추가 시 잘못된 쿼리와 회귀 발생 가능 |
| F2 | 필터 상태가 로컬 상태에 갇힘 | 탭 선택과 색상 선택이 URL에 반영되지 않음 | 새로고침, 뒤로가기, 공유 링크, 상세 복귀 흐름이 끊김 |
| F3 | 탭과 색상 필터 접근성 상태 누락 | 선택 상태가 스타일에만 존재 | 키보드, 보조기기, E2E 검증이 불안정 |
| F4 | 스펙 대비 기능 누락 | 검색 진입, 필터 접기, 초기화, 정렬, 공동구매 마감 표시 없음 | 소비자가 조건을 좁히고 다시 풀기 어려움 |
| F5 | 정렬 책임 중복 | API는 `sort`를 지원하지만 프론트에서 별도 최신순 정렬 | 서버 응답 계약과 화면 표시가 어긋날 수 있음 |
| F6 | 카테고리 전용 테스트 부재 | 전용 E2E 파일 없음 | 탭, 색상, 정렬 회귀를 배포 전 잡기 어려움 |

## 개선 방향

- `saleType`은 도메인 계약에 맞춰 `normal | group`만 허용한다.
- 카테고리 탐색 상태는 URL 쿼리를 단일 출처로 둔다.
- 탭, 색상, 정렬, 초기화는 모두 독립적으로 동작하면서 같은 URL 상태를 갱신한다.
- UI 상태는 시각 스타일과 접근성 속성을 함께 갱신한다.
- 정렬과 필터링은 API 쿼리로 요청하고, 프론트는 응답 표시와 사용자 상태 관리에 집중한다.
- 전용 E2E로 소비자 탐색 핵심 흐름을 고정한다.

## 결정

- 필터 상태는 URL 쿼리를 단일 출처로 둔다.
- 판매 방식은 공유 계약의 `SaleType = normal | group`만 사용하며, 배송 방식의 `direct`를 판매 방식으로 사용하지 않는다.
- 카테고리 탭은 `전체 | 공동구매 | 절화 | 난 | 관엽`을 유지한다.
- 색상 필터는 기본 접힘 상태이며, 선택 색상이 있으면 접힌 상태에서도 선택 요약과 초기화 동작을 제공한다.
- 정렬은 API의 `sort` 쿼리로 위임하고, 프론트에서 별도 재정렬하지 않는다.
- 공동구매 카드는 모집 수량 외에 최소 모집 수량과 마감 정보를 함께 노출한다.

## 정합성 검토

| 영역 | 기준 문서/코드 | 검토 결과 | 반영 방식 |
| --- | --- | --- | --- |
| 판매 방식 | `packages/shared/src/order.types.ts`, API `ProductQueryDto` | `normal | group`이 기준 | 소비자 훅과 카테고리 상태에서 `direct` 제거 |
| 카테고리 | `packages/shared/src/product.types.ts` | `cut_flower | orchid | foliage`가 기준 | URL 파서에서 허용값만 통과 |
| 색상 | 공유 `ColorOption` | 기존 UI 목록이 일부 허용값을 빠뜨림 | 색상 칩을 공유 허용값에 맞춰 확장 |
| 정렬 | API `sort` 쿼리 | `latest | popular | price_asc | price_desc` 지원 | 프론트 재정렬 제거, API 쿼리 위임 |
| 화면 스펙 | `docs/design/소비자-2단계-IA.md` | 검색, 접힘, 초기화, 정렬, 공구 정보 누락 | 이번 범위에 포함 |
| 파일 크기 | `AGENTS.md` 500라인 제한 | 단일 페이지 확장 시 위험 | 상수와 쿼리 유틸을 하위 모듈로 분리 |

## URL 계약

| 쿼리 | 값 | 의미 |
| --- | --- | --- |
| `category` | `cut_flower | orchid | foliage` | 카테고리 필터 |
| `saleType` | `group` | 공동구매 필터 |
| `colors` | 쉼표 구분 색상 | 색상 멀티 선택 |
| `sort` | `latest | popular | price_asc | price_desc` | 정렬 |

`전체` 탭은 `category`와 `saleType`을 제거한다. `공동구매` 탭은 `saleType=group`으로 표현한다.

## W5 필터 맥락 계약

- 활성 필터 요약은 URL 쿼리에서 파생한 순수 상태만 사용한다.
- 요약 라벨은 `공동구매`, 카테고리 라벨, 색상 라벨, 정렬 라벨 순서로 보여준다.
- `latest` 정렬은 기본값이므로 활성 필터 라벨에서 제외한다.
- 개별 해제는 같은 URL 계약을 사용한다. 공동구매 해제는 `saleType`만 제거하고, 카테고리 해제는 `category`만 제거하며, 색상 해제는 해당 색상만 제거한다.
- 전체 초기화는 `category`, `saleType`, `colors`, `sort`를 모두 제거해 `/category`로 돌아간다.
- 빈 상태 문구는 활성 필터가 있으면 선택 조건을 확인하도록 안내하고, 조건이 없으면 전체 상품이 없는 상태로 안내한다.

## 화면 범위

- 헤더 우측에 검색 진입 버튼을 제공한다.
- 카테고리 탭은 현재 선택 상태를 시각 스타일과 접근성 속성으로 함께 표현한다.
- 색상 필터는 펼치기/접기, 멀티 선택, 전체 초기화를 지원한다.
- 정렬 바는 총 상품 수와 정렬 선택을 함께 보여준다.
- 로딩, 오류, 빈 상태는 현재 필터 조건에 맞는 메시지를 보여준다.

## 아토믹 태스크

| ID | 작업 | 산출물 | 검증 |

| T2 | 카테고리 상수 분리 | `category/_constants.ts` | 공유 타입 허용값과 UI 라벨 매핑 확인 |

## 작업 순서

1. T1로 기준을 고정한다.
2. T2, T3로 상태 계약을 페이지 밖으로 분리한다.
3. T4로 API 계약 불일치를 먼저 제거한다.
4. T5, T6로 화면 기능을 연결한다.
5. T7, T8로 검증을 고정한다.

## 제외 범위

- 개인화 추천과 사용자별 선호 저장은 포함하지 않는다.
- 색상 다중 선택의 AND/OR 의미 변경은 포함하지 않는다. 현재 API의 포함 조건을 유지하고, 의미 변경은 별도 도메인 결정으로 분리한다.
- 다중 판매자별 카테고리 집계, 재고 집계, 인기순 산식 변경은 포함하지 않는다.

## 검증

- 타입 검사에서 `saleType` 계약 불일치가 없어야 한다.
- 카테고리 전용 E2E는 탭, 색상, 초기화, 정렬, URL 유지, 검색 진입을 검증한다.
- 브라우저 확인에서 `/category`, `/category?saleType=group&colors=레드`, `/category?category=orchid&sort=price_asc`가 정상 렌더링되어야 한다.
