# 소비자앱 MY 탭 주문 안심 개선 — 아토믹 태스크 플랜

> 작성: 2026-06-17
> 근거: 소비자 MY 탭 코드 감사 + Further 범위 합의
> 원칙: **선(先) 설계 후(後) 구현** — 본 문서 확정 후 아토믹 태스크 단위로 진행한다.
> 목표: MY 탭을 단순 이동 메뉴가 아니라 **주문 수령·구매 확정 상황판**으로 개선한다.

---

## 배경

소비자 MY 탭은 현재 프로필, 주문 내역, 알림, 배송지, 홈 화면 추가 버튼을 제공한다.
그러나 스펙의 "나의 주문 내역", "나의 공동구매 참여 내역", "구매 확정", "후기 작성",
"고객센터" 중 일부는 아직 구현되지 않았거나 화면에서 충분히 드러나지 않는다.

Further 논의 결과 이번 작업은 **주문 안심**을 중심으로 잡았다.
목록과 상세를 모두 얇게 보강하되, 상세 화면에서는 **수령·확정 행동**을 가장 분명히
보여준다. 특히 **구매 확정은 배송 완료 또는 픽업 완료 이후에만 노출**한다.

## 설계 결정

### D1. 이번 개선의 중심은 "주문 안심"이다

MY 탭의 1차 개선 목표는 주문 상태를 더 믿을 수 있게 만들고, 상세 화면에서 다음 행동을
분명히 보여주는 것이다.

- 포함: 주문 목록 상태 신호, 주문 상세 수령 정보, 구매 확정 노출 조건, 상태별 안내.
- 제외: 고객센터, 후기 작성 화면, 알림 서버 동기화, 배송지 관리 UX 고도화.

### D2. 목록과 상세를 모두 얇게 보강한다

목록은 "어떤 주문을 눌러야 하는지" 판단하는 입구로 둔다. 상세는 "지금 무엇을 해야 하는지"
끝내는 화면으로 둔다.

- MY 메인 목록: 일반 주문과 공동구매를 구분하고, 행동 신호를 짧게 표시한다.
- 주문 상세: 픽업 코드, 운송장, 구매 확정 버튼 주변에 상태별 안내를 추가한다.

### D3. 주문 상세의 1차 행동은 수령·확정 중심이다

상세 화면에서 가장 먼저 보강할 행동은 다음 세 가지다.

1. 거점 픽업 주문은 수령 가능 상태부터 픽업 코드를 크게 보여준다.
2. 택배 주문은 운송장 정보가 있으면 바로 보이고, 없으면 준비 중 안내를 보여준다.
3. 배송 완료 또는 픽업 완료 이후에만 구매 확정 버튼을 보여준다.

### D4. 구매 확정은 조기 노출보다 상태 정확성을 우선한다

구매 확정은 돈과 주문 상태가 바뀌는 행동이다. 빠른 접근보다 오동작 방지가 우선이다.

- 노출 가능 상태: `DELIVERED`, `PICKED_UP`.
- 이미 확정된 상태: `REVIEWED`는 완료 문구만 보여준다.
- 노출 금지 상태: `ACCEPTED`, `PREPARING`, `DELIVERING`, `HUB_ARRIVED`, `RECRUITING`, `CONFIRMED`, `CANCELLED`.

## 데이터·상태 기준

| 상태 | 목록 신호 | 상세에서 보이는 행동 |
|------|-----------|----------------------|
| `RECRUITING` | 모집 중 | 공구 참여 취소와 환불 안내는 현행 유지 |
| `CONFIRMED` | 주문 확정 | 배송 준비 전 안내 |
| `ACCEPTED` | 결제 완료 | 준비 시작 전 안내 |
| `PREPARING` | 준비 중 | 수령·운송장 대기 안내 |
| `DELIVERING` | 배송 중 | 택배 운송장 또는 배송 중 안내 |
| `HUB_ARRIVED` | 수령 필요 | 픽업 코드 표시, 구매 확정은 아직 미노출 |
| `PICKED_UP` | 확정 가능 | 구매 확정 버튼 표시 |
| `DELIVERED` | 확정 가능 | 구매 확정 버튼 표시 |
| `REVIEWED` | 확정 완료 | 완료 안내만 표시 |
| `CANCELLED` | 취소됨 | 취소 사유와 후속 안내 |

## 아토믹 태스크 목록

### [ ] T1 — MY 주문 표시 순수 로직 분리

**변경 파일:** `apps/consumer/src/app/mypage/_lib.ts` 신규,
`apps/consumer/src/app/mypage/_client.tsx`

- 주문 상태별 목록 신호를 계산하는 순수 함수를 만든다.
- 일반 주문과 공동구매 참여 내역을 구분하는 그룹 함수를 만든다.
- 날짜 포맷, 배송 방식 라벨, 금액 포맷을 UI에서 분리한다.
- `OrderCard`는 계산된 표시 모델만 받아 렌더링한다.

**정합성 확인:**
- [ ] `PENDING`은 소비자 주요 상태로 강조하지 않는다.
- [ ] 공동구매 주문은 목록에서 일반 주문과 시각적으로 구분된다.
- [ ] 기존 주문 카드 클릭 경로는 유지된다.
- [ ] `_client.tsx`가 500라인 미만을 유지한다.

### [ ] T2 — MY 목록에 행동 신호 추가

**변경 파일:** `apps/consumer/src/app/mypage/_client.tsx`

- 목록 주문 카드에 `수령 필요`, `확정 가능`, `배송 중`, `모집 중`, `취소됨` 같은 짧은 신호를 추가한다.
- 공동구매 주문은 `[공동구매]` 표기를 유지하되 상태 신호와 중복되지 않게 정리한다.
- 빈 상태 문구는 "주문 내역이 없습니다"를 유지하되 다음 행동을 과하게 유도하지 않는다.

**정합성 확인:**
- [ ] 긴 배송지·상태명이 모바일 카드에서 줄바꿈되어도 레이아웃이 깨지지 않는다.
- [ ] 색상은 `var(--color-*)` 토큰만 사용한다.
- [ ] 카드 높이가 상태별로 과도하게 흔들리지 않는다.

### [ ] T3 — 주문 상세 행동 모델 분리

**변경 파일:** `apps/consumer/src/app/mypage/orders/[id]/_lib.ts` 신규,
`apps/consumer/src/app/mypage/orders/[id]/_client.tsx`

- `canConfirmPurchase(order)`를 순수 함수로 분리한다.
- `getReceiptAction(order)`로 픽업 코드, 운송장, 대기 안내를 계산한다.
- `getOrderStatusNotice(order)`로 상태별 안내 문구를 계산한다.
- 컴포넌트는 계산 결과를 받아 표시만 담당한다.

**정합성 확인:**
- [ ] 구매 확정은 `DELIVERED`, `PICKED_UP`에서만 가능하다.
- [ ] `REVIEWED`는 구매 확정 버튼 대신 완료 안내만 보여준다.
- [ ] `HUB_ARRIVED`에서는 픽업 코드는 보이지만 구매 확정 버튼은 보이지 않는다.
- [ ] 순수 함수 단위 테스트를 추가한다.

### [ ] T4 — 주문 상세 수령·운송장 안내 보강

**변경 파일:** `apps/consumer/src/app/mypage/orders/[id]/_client.tsx`

- 픽업 코드는 `HUB_ARRIVED`, `PICKED_UP`, `REVIEWED`에서만 표시하는 현행 조건을 유지한다.
- 택배 주문에 운송장 정보가 있으면 택배사와 운송장번호를 한 묶음으로 보여준다.
- 택배 주문인데 운송장 정보가 없고 배송 전 상태라면 "판매자가 상품을 준비 중입니다" 수준의 대기 안내를 표시한다.
- 안내는 주문 상세 상단 정보 카드 아래에 배치해 구매 확정보다 먼저 읽히게 한다.

**정합성 확인:**
- [ ] 운송장 정보가 일부만 있어도 빈 라벨이 나오지 않는다.
- [ ] 픽업 코드가 없는 거점 주문에서 빈 카드가 나오지 않는다.
- [ ] 취소 주문에서는 수령 안내보다 취소 안내가 우선한다.

### [ ] T5 — 구매 확정 액션 안정화

**변경 파일:** `apps/consumer/src/app/mypage/orders/[id]/_client.tsx`,
필요 시 `apps/consumer/src/hooks/useOrderStatus.ts`

- 구매 확정 버튼 노출 조건을 `canConfirmPurchase(order)`로 통일한다.
- 구매 확정 성공 후에는 로컬 `confirmed` 상태만 바꾸지 말고 상세 데이터를 재조회하거나 표시 모델을 `REVIEWED`에 맞춘다.
- API 실패 시 조용히 실패하지 않고 화면 안에 오류 안내를 보여준다.

**정합성 확인:**
- [ ] API 실패 시 버튼이 무한 로딩 상태로 남지 않는다.
- [ ] 성공 후 버튼 문구가 "구매 확정 완료"로 안정적으로 바뀐다.
- [ ] `CANCELLED` 주문에는 구매 확정 버튼이 나오지 않는다.
- [ ] 구매 확정 API 경로와 인증 토큰 사용 방식은 기존 계약을 유지한다.

### [ ] T6 — refetch·lint 선결 결함 수정

**변경 파일:** `apps/consumer/src/hooks/useOrders.ts`,
`apps/consumer/src/hooks/useAddresses.ts`,
`apps/consumer/src/hooks/useNotifications.ts`

- `useAddresses` 조회 효과가 `_tick` 변경에도 재실행되게 한다.
- `useNotifications`의 `forEach` 콜백 반환 Biome 오류를 제거한다.

**정합성 확인:**
- [ ] `refetch()` 호출 시 실제 API가 다시 호출된다.
- [ ] 배송지 저장 후 목록 갱신은 본 작업의 부수 안정화로 확인만 하고, UI 고도화는 별도 범위로 둔다.
- [ ] 기존 소비자 앱 전역 lint 경고는 본 태스크에서 새로 늘리지 않는다.
