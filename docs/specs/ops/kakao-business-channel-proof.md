## 공개 판매상품 계약

- 공개 상품 목록 API는 `isActive=true`이면서 `testOnly!==true`인 상품만 반환한다. 공개 요청에서 비활성 상품 조회를 요구해도 이 경계를 완화하지 않는다.
- 공개 상품 상세 API는 비활성 상품과 `testOnly=true` 상품을 상품 없음으로 처리한다.
- E2E 시드는 고정 시험용 상품 두 건에 `testOnly=true`를 반드시 기록하고, 실제 소비자 배송 슬롯을 만들 상점을 고를 때 시험용 상품을 제외한다.
- 공동구매 공개 상태는 목표 수량과 `recruitDeadline`을 함께 판정한다. 목표 수량을 채웠거나 모집기한이 지났거나 설정이 없으면 진행 중 목록에서 제외한다.
- 모집이 끝난 공동구매 상세에서는 장바구니와 결제 동선을 모두 비활성화하고 수량 마감·기한 마감·판매 준비 상태를 구분해 표시한다.
- 2026년 8월 11일 운영 Firestore의 고정 `e2e-` 상품 두 건을 삭제하지 않고 `isActive=false`, `testOnly=true`로 변경했다. 같은 관리 스크립트의 `--restore`로 `testOnly=true`를 유지한 채 활성 상태만 복구할 수 있다.
- 실제 판매상품의 활성 여부, 가격, 재고, 배송일은 사업 운영 판단이므로 이번 정리에서 임의로 변경하지 않는다.
- 코드 merge commit `098ad98c72a8bdcb5e3c1a95ed2c6b3287cf0ab2`의 consumer와 API production 배포가 성공했고 운영 API·데스크톱·375×812 모바일에서 이 계약을 재확인했다.

## 공개 법적 고지 증거 계약

- 개인정보처리방침의 정본 경로는 `https://greenlove.co.kr/privacy`다.
- 이용약관의 정본 경로는 `https://greenlove.co.kr/terms`다.
- 두 경로는 비로그인 상태에서 HTTP 200으로 열려야 하며 로그인 화면으로 이동하면 안 된다.
- 개인정보처리방침은 첫 화면에서 서비스명 `그린러브`, 운영자 `디어 오키드`, 시행일을 확인할 수 있어야 한다.
- 이용약관은 현재 상용 주문·결제·배송을 운영하지 않는다는 서비스 경계를 명시해야 한다.
- 두 문서는 상호 이동 링크를 제공하고 홈 사업자 정보 footer에서도 각각 한 번의 클릭으로 열려야 한다.
- 모바일 375×812 화면에서 가로 스크롤이 없어야 하며 고정 하단 내비게이션이 마지막 문단·문의처·문서 링크를 가리면 안 된다.
- 검증 시 페이지 제목, 운영 관계, 시행일, 고객센터 이메일·전화, 상호 문서 링크, 브라우저 콘솔 오류 0건을 기록한다.

카카오 심사 설명은 다음 사실만 사용한다.

> 디어 오키드가 그린러브 서비스를 직접 운영하며, 홈페이지의 사업자 정보·개인정보처리방침·이용약관에서 동일한 운영 주체를 확인할 수 있습니다.

홈페이지 주소는 `https://greenlove.co.kr`로 제출한다. 사업자등록증 원본, 비공개 계정 정보, 주민등록번호·생년월일, 발급번호가 포함된 자료를 새로 첨부하지 않는다. 이번 반려 사유는 홈페이지에서 필수 법적 고지를 확인하기 어려워 채널과 사업자의 연결성을 검증할 수 없었다는 점으로 기록하며, 고객센터 전화번호 불일치로 바꾸어 해석하지 않는다.

## 증거와 버전 관리

- 법적 문안 정본은 `docs/specs/legal/consumer-legal-documents.md`, 공개 사업자 정본은 `apps/consumer/src/lib/publicBusinessInfo.ts`에서 관리한다.
- 배포 전에는 테스트·타입검사·lint·production build와 로컬 데스크톱·모바일 검증을 통과해야 한다.
- 배포 후에는 main 병합 SHA, consumer Vercel 배포 URL·상태, 운영 두 경로의 HTTP 상태와 비로그인 브라우저 검증 결과를 재심사 보고서에 기록한다.
- seller·driver가 Ignored Build Step으로 건너뛰었는지, Railway API가 consumer-only 변경으로 재배포되지 않았는지 확인한다. 예상 밖 배포가 생겨도 임의 롤백하지 않고 원인을 기록한다.
- 법적 문서가 바뀌면 시행일과 이전 버전 보관 경로를 갱신하고 카카오 제출 증거가 가리키는 운영 문서 버전을 함께 기록한다.
- production 검증 완료는 카카오 재심사 제출 승인이 아니다. 카카오 화면 입력·제출은 사용자의 별도 명시적 승인 후에만 수행한다.
